# 图片项目 Brief 弹窗化设计

## 目标

简化图片素材项目详情页，删除页面底部重复的 Brief 展示与编辑区域。Brief 只通过页面顶部的“编辑 Brief”按钮进入弹窗编辑，减少页面高度并保持创作工作流聚焦。

## 页面结构

图片项目详情页保留：

- 顶部项目名称、项目类型、平台、目标语言、画面规格和商品名称摘要。
- 顶部“编辑 Brief”文字按钮。
- 图片提示词、参考图、生成设置、图片版本和提示词版本。

图片项目详情页删除：

- 底部 `Brief Summary` 区域。
- 底部 `Project Brief / 项目与 Brief` 展示和编辑区域。
- 底部 Brief 的折叠、只读摘要或第二编辑入口。

页面中只能存在一个用户可见的“编辑 Brief”入口。

## 编辑弹窗

点击顶部“编辑 Brief”后打开现有 Brief 编辑弹窗。

桌面端：

- 表单使用两列布局。
- 项目名称、图片用途、投放平台、画面比例、目标语言、商品名称、视觉风格和目标受众按两列排列。
- 广告需求和核心卖点分别占整行。
- 弹窗内容超过视口时，表单区域纵向滚动；标题和底部操作按钮保持可用。

移动端：

- 在窄于 `sm` 断点时改为单列布局。
- 所有字段宽度不超过视口。
- 弹窗内容纵向滚动，不出现页面或弹窗水平溢出。

## 数据与状态

保持现有行为不变：

- 使用现有 Brief 表单状态、校验和保存接口。
- 保存成功后刷新项目并关闭弹窗。
- 保存失败时保留用户输入并在弹窗中显示错误。
- Brief 变更产生的精确失效传播规则不变。
- 视频项目的 Brief 展示和编辑不在本次范围内。

## 组件边界

- `ImageProjectWorkspace` 负责顶部入口和图片创作内容。
- 现有 Brief 弹窗组件继续负责表单、校验、保存状态和响应式布局。
- 删除仅供图片项目底部展示使用的 Brief 渲染调用；若相关组件仍被视频项目或其他页面使用，不删除共享组件。
- 不修改后端 API、数据库模型和资产结构。

## 测试

前端组件测试覆盖：

- 图片项目详情页不再出现 `Brief Summary`、`Project Brief` 或底部“项目与 Brief”区域。
- 顶部“编辑 Brief”按钮为唯一可见入口。
- 点击按钮打开弹窗，取消可关闭。
- 修改并保存 Brief 继续调用现有 API，成功后刷新并关闭。
- 保存失败保留弹窗和输入。

浏览器测试覆盖：

- 桌面端弹窗为两列，长文本字段占整行。
- 390px 移动视口弹窗切为单列。
- 桌面和移动端均无水平溢出、字段重叠或操作按钮遮挡。
- 删除底部区域后，页面末尾停在提示词版本或图片创作内容，不再重复展示 Brief。

## 非目标

- 修改 Brief 字段或校验规则。
- 修改 Brief 保存 API 或失效传播。
- 为 Brief 增加自动保存、版本历史或只读预览。
- 调整视频项目详情页。
