# AIGC 产物节点命名竞态修复设计

## 问题

生成任务已经通过 Seed 2.0 Mini 得到合法名称，资产也保存了
`generated_name`，但画布节点最终仍显示默认名称。

运行时证据表明存在两个问题：

1. 原子提交只尝试更新执行生成任务的模型节点，而用户实际查看的是与生成
   输出相连的图片或视频产物节点。
2. 生成完成后的前端自动保存可能使用旧草稿覆盖服务端刚写入的名称。当前前端
   rebase 只记录“哪些节点名称以服务端为准”，仍依赖再次查询到的 Pipeline
   名称；如果查询前名称已被旧草稿覆盖，权威值也会变成空。

## 方案

### 后端

- 从 Run definition snapshot 中查找生成任务节点直接连接的图片或视频输出节点。
- 成功命名时，在同一仓储事务中将 AI 名称写入这些产物节点的
  `custom_name`。
- 模型节点继续保留模型职责名称，不再作为自动命名目标。
- 多个直接产物节点共享同一个本次生成名称，并且整个局部更新只增加一次
  Pipeline revision。
- 资产继续保存冻结的 `generated_name`、命名模型和命名状态。

### 前端

- 从成功 Run 的 `result.naming.name` 构造“产物节点 ID -> 权威名称”映射。
- Pipeline 刷新和 autosave rebase 时直接使用该映射，不再仅依赖远端
  `custom_name`。
- rebase 只覆盖对应产物节点的 `custom_name`，保留其他本地编辑。
- 后续 autosave 必须携带 AI 名称，不能重新写回空值或旧名称。

## 错误处理

- 命名失败或无合法名称时不修改任何节点名称。
- 没有直接图片或视频输出节点时保持现有降级行为，不影响生成成功。
- 已删除的输出节点不重建；并发用户编辑仍通过 revision 冲突与 rebase 合并。

## 验证

- 仓储测试覆盖单个和多个下游产物节点、一次 revision 递增、其他节点不变。
- 前端测试覆盖服务端名称已被旧保存覆盖时，Run 中的名称仍能恢复产物节点，
  且下一次 autosave 不写回空值。
- 回归验证文生图、图生图、图片编辑和生视频的命名与下载。
- 使用目标画布重新生成，确认“图片节点2”更新为 AI 名称并在刷新后保持。
