# 分镜视频提示词时间轴与语音字幕设计

## 背景

当前单分镜的默认视频提示词仅拼接画面描述、视觉提示、时长和旁白。多个分镜合并后，原始 `video_prompt` 被清空，描述和旁白只按换行拼接，无法表达各段剧情在合并视频中的明确时间区间。

本设计参考火山引擎《Doubao Seedance 2.5 提示词指南》：

- 使用连续时间区间，例如 `[0s-4s]`、`[4s-8s]`。
- 避免时间轴空洞、剧情过密和过度切镜。
- 使用清晰、通用的景别、运镜和机位描述。
- 转场应明确触发时间和方式。
- 提示词应避免前后矛盾，并补齐分镜素材未表达的动作、运镜和剧情逻辑。

参考文档：https://docs.volcengine.com/docs/82379/2607689?lang=zh#prompt-writing

## 目标

1. 单分镜和合并分镜统一生成适配 Seedance 2.5 的结构化视频提示词。
2. 所有提示词都包含从 0 秒开始、连续无空洞的时间区间。
3. 合并后保留每个来源镜头的真实时长边界和剧情顺序。
4. 用户手动编辑的创作意图得到保留，同时自动补齐时间轴、镜头、语音字幕和负向约束。
5. 有旁白时要求生成普通话语音，并将对应简体中文字幕同步显示在画面中。
6. 继续清空合并分镜的参考素材、首帧和旧视频，不删除资产库中的原始素材。

## 非目标

- 不新增独立的结构化时间轴数据库字段。
- 不使用 FFmpeg 或字幕轨进行确定性字幕烧录。
- 不修改 Seedance 任务参数、视频时长上限或参考素材数量限制。
- 不实现逐字级语音识别与字幕对齐。

字幕采用提示词控制，因此受生成模型能力影响，不保证与后处理烧录相同的逐字确定性。

## 方案决策

采用集中式提示词构建器，不修改数据库结构。

新增独立后端模块，集中提供：

- `build_single_shot_video_prompt(shot)`：普通分镜提示词。
- `build_merged_shot_video_prompt(shots)`：按来源分镜构建连续时间轴。
- `normalize_video_prompt(shot, custom_prompt)`：生成前统一规范化。
- `strip_narration_label(value)`：清理 `旁白/字幕：`、`旁白：`、`字幕：` 等重复前缀。

所有入口使用同一套格式，避免 schema、仓库和生成服务各自拼接提示词。

## 提示词契约

最终提示词按以下固定结构组织：

```text
【整体要求】
生成指定画幅、总时长 N 秒的连贯广告视频。保持主体、服装、场景和光影连续。

【连续时间轴】
[0s-5s]
剧情：来源镜头的画面描述。
镜头：来源镜头的视觉提示、景别、运镜和机位。
语音：普通话旁白“指定文本”。
字幕：同步显示“指定文本”。

[5s-9s]
……

【语音与字幕】
生成自然、清晰的普通话语音；字幕与对应语音逐字一致并同步出现。
字幕使用简体中文，位于画面底部安全区，白字、黑色描边，最多两行。
只显示指定字幕，不添加额外对白字幕、说明文字或水印。

【负向约束】
时间轴必须连续；不要遗漏或调换剧情顺序；避免过度切镜、主体变形、
口型明显错位、字幕乱码或遮挡主体。
```

### 单分镜

单分镜也使用一个完整区间 `[0s-Ns]`。这保证普通分镜与合并分镜的提示词语义一致。

### 合并分镜

根据来源镜头排序后累积时长：

- 5 秒、4 秒、6 秒生成 `[0s-5s]`、`[5s-9s]`、`[9s-15s]`。
- 支持小数时长，去除无意义的尾随零。
- 每段分别保留 description、visual_prompt 和 narration。
- 合并后把构建结果保存到 `video_prompt`，不再将其设为 `None`。

### 无旁白分镜

时间段写明“无对白，仅生成环境音与动作音，不显示字幕”，并禁止模型自由添加台词。

### 用户手动提示词

- 普通文本提示词作为“创作意图”写入对应时间段，固定约束仍由构建器补齐。
- 已包含新版固定章节的提示词执行幂等规范化，避免重复嵌套。
- 用户不能通过省略固定章节绕过时长、连续时间轴和字幕约束。

## 数据流

### 获取和编辑配置

1. `StoryboardShot.effective_video_prompt` 调用统一构建器。
2. 无自定义提示词时返回新版默认格式。
3. 前端继续使用现有配置接口和编辑器，不增加表单字段。
4. 保存后仍写入 `video_prompt`。

### 合并分镜

1. 端点校验相邻性和总时长不超过 30 秒。
2. 仓库按 index 排序来源分镜。
3. 在删除来源分镜前构建带连续时间戳的合并提示词。
4. 合并 description、visual_prompt 和 narration。
5. 保存新 `video_prompt`。
6. 清空参考素材、首帧、图片和视频关联，状态重置为 `draft`。
7. 重新编号并标记下游产物失效。

Memory 与 MySQL 仓库必须保持相同语义。

### 生成视频

1. 路由读取分镜及其有效提示词。
2. 生成服务调用 `normalize_video_prompt`。
3. 规范化后的完整文本作为 Seedance 请求中的 text content。
4. 保持 `generate_audio=True`。
5. 资产 metadata 保存最终实际发送的提示词，便于排查。

## 长度与错误处理

- 提示词最大长度统一为 12000 字符；MySQL `TEXT` 无需迁移。
- 构建器优先保留时间戳、剧情顺序和旁白全文。
- 构建器先预留固定章节、全部时间戳和旁白所需长度，再把剩余字符预算平均分配给各段 description 和 visual_prompt。
- 超出长度预算时只压缩 description 和 visual_prompt，不截断时间戳或旁白。
- 若构建后仍无法满足长度限制，返回明确的 validation error，不发送残缺提示词。
- 原有合并数量、相邻性、30 秒上限及参考素材互斥校验保持不变。

## 兼容性

- 现有 `video_prompt=None` 的数据自动使用新版默认提示词，无需迁移。
- 现有自定义提示词被保留为创作意图。
- 合并前已有的参考素材文件仍保留在资产库，只清空分镜关联。
- API 响应结构不新增字段，前端类型无破坏性变化。

## 测试

### 单元测试

- 单分镜包含 `[0s-Ns]` 和固定章节。
- 合并分镜按真实时长生成连续区间，覆盖整数和小数。
- 时间轴从 0 开始、终点等于合并总时长、区间无空洞和重叠。
- 清理重复旁白标签。
- 有旁白时包含普通话语音、逐字字幕和字幕样式约束。
- 无旁白时仅生成环境音/动作音并禁止字幕。
- 自定义提示词被保留，规范化具有幂等性。
- 长文本压缩不丢失时间戳和旁白。

### 仓库与 API 测试

- Memory/MySQL 合并后保存相同的时间轴提示词。
- 合并后参考素材、首帧和旧视频仍被清空。
- 配置接口对普通分镜返回新版 `effective_video_prompt`。
- 生成服务收到规范化后的最终提示词。
- 资产 metadata 保存最终提示词。

### 回归验证

- `.venv/bin/python -m pytest backend/tests/`
- `npm test`
- `npm run typecheck`

## 验收标准

1. 任意普通分镜的有效视频提示词都包含 `[0s-Ns]`。
2. 任意合法合并分镜的时间轴完整覆盖 0 到总时长，且每段对应原来源镜头。
3. 有旁白的每个时间段都明确要求普通话语音和同步简体中文字幕。
4. 合并后不保留旧参考关联或旧视频，但保留原始素材文件。
5. 手动提示词不会绕过固定生成约束，也不会被静默丢弃。
6. 后端与前端相关测试全部通过。
