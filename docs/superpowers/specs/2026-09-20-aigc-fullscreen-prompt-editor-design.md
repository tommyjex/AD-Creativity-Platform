# AIGC 全屏提示词编辑器设计

## 背景

AIGC 画布中的长提示词目前同时受两个紧凑区域限制：

- 画布文本节点仅用于摘要展示，长内容在节点中被截断；
- 右侧检查器的“基础文本”文本框高度有限，虽然支持滚动，但无法高效浏览、
  选择和编辑完整提示词。

长提示词是生视频等节点的核心创作输入，应具备不截断、可集中编辑、不会挤压画布
操作空间的工作流。

## 目标

提供“检查器摘要 + 全屏提示词编辑器”的交互：

1. 画布节点与右侧检查器保持紧凑，承担定位和预览；
2. 用户可通过明确入口进入近全屏编辑器，完整查看并编辑提示词；
3. 编辑过程延续当前节点配置更新、撤销和自动保存行为；
4. 不改变现有提示词优化请求、结果写回或下游节点连接逻辑。

## 不在范围

- 不改变文本节点在画布中的摘要渲染；
- 不新增富文本、Markdown 渲染、版本对比或多用户协作；
- 不改变提示词长度上限、坐标标签限制或 BBox 引用编辑；
- 不将提示词优化弹窗重构为全屏工作流。

## 交互设计

### 检查器摘要

右侧检查器的“基础文本”改为固定高度的预览区：

- 显示最多约 6 行文本，可垂直滚动阅读；
- 始终显示当前字符数和长度上限；
- 点击预览区或其右侧的“展开编辑”图标按钮，打开全屏编辑器；
- 保留“优化提示词”作为独立操作，不因展开编辑而改变入口位置。

预览区不再作为长文本的主要编辑面，避免拖动调整检查器高度、滚动条抢占和画布空间
冲突。

### 全屏编辑器

全屏编辑器使用 Dialog，桌面端占据视口主要区域，移动端全屏：

- 顶部固定：文本节点名称、字符计数、关闭图标；
- 中间可滚动区域：等宽字体的多行 `Textarea`，自适应占满可用高度，自动换行；
- 底部固定：取消与应用按钮；
- 保持深色工作台配色，与现有提示词优化弹窗一致；
- 不展示重复的功能说明或快捷键说明文本。

编辑器内容始终读取当前有效文本：有上游连接时使用有效的 Run 文本或本地 override，
无上游连接时使用节点的本地文本。内容不会因打开弹窗被裁切、折叠或格式化。

### 提交、取消与快捷键

- 文本输入仅在点击“应用”或按下 `Cmd/Ctrl+Enter` 后一次性写回节点配置；
- `Esc` 与“取消”关闭编辑器并丢弃本次未应用的草稿；
- 点击关闭图标的行为等同于取消；
- 若内容没有变化，应用后仅关闭编辑器，不创建新的撤销记录；
- 当文本来自上游且当前节点不可编辑时，编辑器只读，且不显示应用按钮。

打开编辑器后，草稿与画布内联编辑相互隔离。编辑器打开期间若节点文本或有效 Run
上下文变化，应用时使用现有的乐观并发保护：提示用户内容已变化，不覆盖较新的文本。

### 可访问性

- Dialog 标题具备可访问名称；
- 编辑区域使用明确的 `aria-label`；
- 图标按钮提供 `title` 和 `aria-label`；
- 焦点打开时进入编辑区域，关闭后回到触发入口；
- 键盘操作与按钮操作具有完全相同的提交或取消语义。

## 实现边界

主要修改集中在文本节点的检查器编辑组件：

- 新建一个局部的 `PromptFullscreenEditor` 组件或等价的受控 Dialog；
- `AigcPromptEditor` 仅负责提供当前有效文本、可编辑状态及受控更新回调；
- 不修改 `buildPromptOptimizationRequest`、提示词优化 API、画布节点定义或后端模型服务；
- 复用现有 `Dialog`、`Textarea`、`Button` 和 Lucide 图标。

## 测试与验收

- 长提示词在全屏编辑器中完整渲染，且不出现 CSS 截断；
- 编辑、点击应用、`Cmd/Ctrl+Enter` 均能写回完整文本；
- 取消、关闭图标和 `Esc` 不写回草稿；
- 无修改时应用不产生撤销历史；
- 上游不可编辑文本以只读形式打开，不能提交；
- 检查器预览区点击与图标入口均可打开编辑器；
- 前端组件测试覆盖桌面与移动布局相关类名；
- 运行 AIGC 提示词编辑器 Vitest、ESLint，并用 Playwright 在桌面和手机视口检查
  全屏编辑器的可见范围、键盘操作和无文本遮挡。
