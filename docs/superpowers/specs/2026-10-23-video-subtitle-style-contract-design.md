# 视频字幕样式数据契约设计

## 背景

现有视频字幕定位实验可以提取文字、时间区间和 BBox，并将模型输出的
1000x1000 归一化坐标反算为视频展示空间中的像素坐标。真实视频中可能同时
存在大标题、正文、小号说明和脚注。后续链路会翻译提取结果，再将译文压制到
无字幕原视频，因此只保留文字和位置不足以复现原视频的字号层级。

本设计在现有实验接口上增加轻量、稳定的样式契约。它同时保留视觉角色和实测
值，使翻译链路无需重新理解原视频，也为后续逐条样式化压制提供直接输入。

## 目标

- 区分 `headline`、`body` 和 `footnote` 三种视觉字号层级。
- 保留每一视觉行的相对字高、位置、对齐方式和多行分组关系。
- 翻译时只替换文字，原样透传时序和样式元数据。
- 小号说明和脚注不得因字号小或置信度低而被硬过滤。
- 样式字段异常只降级对应字段，不使有效字幕文字丢失或整次请求失败。
- 新契约兼容缺少样式字段的历史结果。
- 为后续 ASS 压制定义稳定的消费规则，但本轮不实现翻译或压制。

## 非目标

- 不识别字体家族、精确字重、颜色、描边、阴影或动画。
- 不开发前端，不修改画布节点或现有 MediaKit 字幕资产链路。
- 不在本轮实现字幕翻译、无字幕视频生成或 ASS 压制。
- 不保证模型估算值达到像素级排版测量精度。
- 不改变 Files API、默认 `sampling_fps=2.0`、视频安全下载或坐标反算规则。

## 方案选择

### 方案 A：只返回视觉角色

每条字幕只增加 `visual_role`。结构简单，但同为正文的不同字号会被压成同一
大小，无法可靠复现原片。

### 方案 B：视觉角色加实测值

每条字幕同时返回三级视觉角色、相对字高、对齐方式和多行分组信息。视觉角色
提供稳定语义，实测值承载视频内的实际差异。模型漏报某项时，后端可从 BBox
或默认规则逐字段降级。

本设计采用方案 B。它满足翻译后复现字号的核心目标，又不会引入完整字体样式
识别的高不确定性。

### 方案 C：完整视觉样式重建

额外识别字体、颜色、字重、描边和阴影。表达能力最高，但模型输出稳定性、
字体可用性和渲染一致性都无法在当前预研中保证，暂不采用。

## 数据契约

### 视觉角色

`visual_role` 只描述视觉字号层级，不承载“对话”“产品标签”等内容语义：

- `headline`：主标题、章节标题或视觉上显著放大的核心文案。
- `body`：普通对话字幕、正文说明和常规标签。
- `footnote`：小号补充说明、条件说明、免责声明或脚注。

无法识别、缺失或非法的角色统一降级为 `body`。首版不增加内容语义字段，避免
视觉层级和文字用途混杂。

### 单条字幕

规范化后的 API 响应中，每条字幕包含：

```json
{
  "text": "Example subtitle",
  "start_ms": 1200,
  "end_ms": 3600,
  "visual_role": "headline",
  "font_height_ratio": 0.062,
  "bbox_normalized": [120, 80, 880, 150],
  "bbox_pixels": [230, 86, 1689, 162],
  "alignment": "center",
  "block_id": "block_07",
  "line_index": 0
}
```

新增字段定义：

| 字段 | 类型 | 约束 | 含义 |
|---|---|---|---|
| `visual_role` | string enum | `headline/body/footnote` | 视觉字号层级 |
| `font_height_ratio` | number | `0 < value <= 1` | 可见字高占视频展示高度的比例 |
| `alignment` | string enum | `left/center/right` | 文字在其字幕块内的水平对齐方式 |
| `block_id` | string | 1..64 个安全字符 | 关联同一视觉字幕块中的多行 |
| `line_index` | integer | 从 0 开始 | 行在对应字幕块中的视觉顺序 |

`text` 继续表示单个视觉行，不允许包含换行符。同一多行字幕的各行使用相同
`block_id`，通常共享 `start_ms` 和 `end_ms`，但保留各自独立的 BBox、
`font_height_ratio` 和 `line_index`。

### 字高定义

`font_height_ratio` 描述可见字形的估算高度，而不是字号点数：

```text
font_height_ratio = estimated_glyph_height / display_height
```

使用相对值可以跨源视频和输出分辨率缩放。模型应基于画面中实际可见字形估算，
而不是根据 `visual_role` 填入固定值。BBox 应紧贴单行文字区域，供后端在模型
未提供有效比例时计算回退值：

```text
font_height_ratio = (bbox_y_max - bbox_y_min) / 1000
```

BBox 回退值包含行框留白，精度低于有效的模型估算值，但仍优于全局固定字号。

## 提取与规范化

### 模型输出

严格 JSON Schema 为每条字幕增加 `visual_role`、`font_height_ratio`、
`alignment`、`block_id` 和 `line_index`。提示词同时要求：

- 扫描整个画面，保留大标题、普通正文、小号说明和脚注。
- 不得因为文字较小而省略符合目标定义的文字。
- 按视觉行拆分多行内容，每行具有独立 BBox。
- 同一视觉块中的多行共享 `block_id`，并按从上到下顺序设置 `line_index`。
- 角色根据相对视觉层级判断，字高比例根据实际画面估算。
- 不输出 Logo、水印、包装印刷、界面按钮或无关背景文字。

新调用的模型输出必须包含五个样式键，但每个样式值允许为 `null`。核心字段
`text`、`start_ms`、`end_ms` 和 `bbox` 不允许为 `null`。模型侧 Schema 是
生成约束，不作为应用信任边界；后端仍需容忍 Provider 返回偏离 Schema 的
单个样式值。规范化后的 API 响应不包含 `null`，所有样式字段均由后端补全。

### 后端规范化

后端继续权威校验核心文字、时间和 BBox，并按以下顺序规范化样式字段：

1. 合法的模型值直接保留。
2. 非法或缺失 `visual_role` 使用 `body`。
3. 非法或缺失 `font_height_ratio` 使用归一化 BBox 高度。
4. 非法或缺失 `alignment` 根据 BBox 水平中心回退：中心点小于等于 350 为
   `left`，大于等于 650 为 `right`，其余为 `center`。
5. 非法或缺失 `block_id` 使用当前片段序号生成独立块 ID。
6. 非法或缺失 `line_index` 使用 `0`。

样式字段按字段独立降级，不因为一个样式值异常覆盖其他合法样式值。

核心字段仍保持强校验。模型响应不是合法 JSON、顶层结构不合法或没有可解析
字幕数组时，整次请求以 `invalid_model_output` 失败。单个片段的
`text/time/bbox` 不合法时丢弃该片段并记录安全统计；如果模型返回了非空数组
但没有任何有效片段，整次请求失败。该规则避免一条坏数据遮蔽同一视频中的
其他有效字幕，同时不会把完全不可用的响应伪装成“无字幕”。

上述片段级容错规则取代当前实验 Spec 中“任一非法片段导致整次响应失败”的
全有或全无规则。顶层结构和全部片段不可用时仍保持硬失败。

### 输出兼容

新调用返回完整的规范化样式字段。读取旧结果时，缺失字段使用相同降级规则，
因此旧数据无需迁移：

- 角色默认为 `body`。
- 字高优先从已有 BBox 计算。
- 对齐根据 BBox 水平中心推导。
- 每条旧字幕形成独立块，`line_index=0`。

## 翻译数据流

翻译阶段只允许修改 `text`，必须原样透传：

- `start_ms` 和 `end_ms`
- `visual_role` 和 `font_height_ratio`
- `bbox_normalized` 和 `bbox_pixels`
- `alignment`
- `block_id` 和 `line_index`

原文与译文通过稳定的字幕条目标识或数组位置关联。翻译服务不得根据译文长度
重新分类 `visual_role`，也不得覆盖原视频测得的字高和位置。

## 后续压制设计

现有 SRT 加全局 `FontSize=18` 无法表达逐条字号和位置。后续压制阶段应生成
ASS 事件：

- ASS 画布尺寸使用目标输出视频的展示尺寸。
- 初始字高由 `font_height_ratio * output_height` 计算。
- BBox 按目标输出尺寸同比缩放，用于定位和可用宽度计算。
- `alignment` 决定文字锚点。
- `visual_role` 只用于缺失值兜底和角色级字号范围约束。
- 同一 `block_id` 按 `line_index` 保持视觉顺序和相对间距。

译文可能比原文更长。渲染器使用实际字体测量文本宽度，先在原始字号以下缩小
以适配原 BBox；达到配置下限后仍溢出时，只在 ASS 渲染层自动换行。自动换行
不回写提取结果，也不改变原始逐视觉行的数据结构。

旧数据继续使用现有全局字号路径作为最终兜底。单条字幕的样式或布局计算失败
时只降级该条，不中断整段视频压制。

## 错误处理与日志

- 核心响应结构无法解析：返回 `invalid_model_output` 和
  `phase=response_validation`。
- 单条核心字段非法：丢弃该条，仅记录字段类别和计数。
- 单条样式字段非法：规范化后保留字幕，并记录对应降级计数。
- Provider 或 Files API 失败：沿用现有阶段化错误契约和清理逻辑。
- 模型原始响应只允许写入受限 TLS-only 事件，不得进入 stdout、API 错误、
  数据库或普通结构化日志。
- 普通日志不得包含字幕全文、完整视频 URL、查询参数或模型思考内容。

成功日志可增加按角色计数、样式降级计数和多行块计数，不记录具体文字。

## 实现边界

本轮只实现：

- 请求和响应 Schema 的样式字段。
- ModelArk 严格 JSON Schema 与任务提示词。
- 样式字段解析、规范化和输出。
- 多行块关联。
- Mock 单元测试、适配器测试和接口契约测试。
- 使用现有多字号测试视频进行一次人工验收。

本轮不实现翻译服务、ASS 生成、FFmpeg 压制或前端展示。后续压制能力应独立
设计和实施，避免实验接口与现有合成服务提前耦合。

## 测试

### Schema 与规范化

- 三种 `visual_role` 均能解析并稳定序列化。
- 非法或缺失角色降级为 `body`。
- 合法 `font_height_ratio` 原样保留。
- 缺失、非数值、非正数或大于 1 的比例使用 BBox 高度回退。
- 左、中、右对齐均能解析；非法值按明确阈值回退。
- 多行字幕共享 `block_id`，`line_index` 连续且顺序稳定。
- 旧结果缺少全部新增字段时仍能生成完整规范化响应。

### 提取契约

- 提示词明确覆盖大标题、正文、小号说明和脚注。
- 多行文字按视觉行拆分，`text` 中不含换行符。
- 每行具有独立 BBox，可共享时间区间。
- Logo、包装印刷和无关背景文字仍被排除。
- 单条样式异常不会丢失合法字幕。
- 单条核心字段异常只丢弃该条；全部片段无效时请求失败。

### 坐标与回归

- 新增字段不改变 1000x1000 BBox 到展示像素坐标的算法。
- 旋转视频仍以展示方向尺寸计算坐标和字高比例。
- 默认 `sampling_fps=2.0` 和 Files API 预处理参数保持不变。
- 普通测试使用模拟响应，不调用真实网络或计费模型。

### 人工验收

使用现有多字号视频执行一次显式真实模型验证，逐项核对：

- 大标题、正文、小号说明和脚注是否完整提取。
- 视觉角色是否符合相对字号层级。
- `font_height_ratio` 是否与画面中字高关系一致。
- 多行字幕是否逐行拆分并正确分组。
- BBox、时间和对齐信息是否可用于后续定位。

真实调用产生费用，不作为普通 CI 必过项。

## 验收标准

- 每个视觉行独立输出，`text` 不含换行符。
- 大标题、正文和脚注可通过 `visual_role` 稳定区分。
- 同一角色内的实际字号差异可通过 `font_height_ratio` 保留。
- 多行字幕可通过 `block_id` 和 `line_index` 恢复视觉顺序。
- 翻译只替换文字即可完整保留时序、位置和字号信息。
- 任一非核心样式字段异常不会导致有效字幕或整次请求丢失。
- 历史无样式结果仍可读取和规范化。
- 新契约可以直接作为后续 ASS 压制设计的输入。
