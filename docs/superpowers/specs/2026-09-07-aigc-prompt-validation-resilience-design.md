# AIGC 提示词优化校验韧性设计

## 背景

生图提示词优化当前把结构规范、输出质量启发式和数据完整性约束统一处理为
`ModelArkTextParseError`，并由 API 统一映射为 HTTP 502。模型只要在 section
顺序、英文措辞、单位写法或关键词选择上偏离后端规则，整个优化结果就不可用。

已确认的误报包括：

- `Composition` 内容有效但位置不是倒数第二；
- `180 度` 被翻译为 `180 degrees`；
- 已优化英文提示词中的 `180-degree` 再次优化。

目标是在不牺牲 BBox、资产引用、品牌、型号、可见文案、明确数量和否定条件的
前提下，让低风险格式或表达差异不再导致“服务不可用”。

## 设计原则

1. 数据完整性约束继续硬失败。
2. 可确定修复的结构差异由后端归一化。
3. 启发式质量规则降级为告警，不阻止返回。
4. 502 只表示供应商失败、响应无法解析或结果无法安全使用。
5. 公开 API 响应仍只包含 `optimized_text` 和
   `optimized_reference_instructions`，不改变前端契约。

## 校验分级

### Hard Fail

以下情况拒绝整个结果：

- Provider 响应不是可解析 JSON，或无法得到非空提示词；
- BBox token、坐标或引用顺序发生变化；
- 引用说明数量与输入不一致；
- 引用资产身份或关系被改变；
- 明确品牌、型号、URL、反引号变量或引号内可见文案丢失；
- 明确产品/对象数量被删除、改变或绑定到其他对象；
- 用户明确否定条件被删除或反转；
- 输出超过协议长度上限。

Hard Fail 返回结构化的优化失败错误；供应商错误继续映射为 502，模型结果不安全
则映射为可识别的 422，避免把校验问题伪装成服务不可用。

### Auto Repair

以下情况在返回前确定性修复：

- 将唯一 `Composition` 移到倒数第二；
- 将唯一 `Negative Prompt` 移到最后；
- trim section label/content，折叠非受保护字面量中的多余空白；
- 去除外层 Markdown 代码围栏；
- 兼容已知字段别名；
- 对等价单位表达和连字符形式做规范化识别；
- 在不改变内容的前提下修复可接受的 label 大小写。

缺少必需 section 时，不凭空生成创意内容。若主提示词仍完整可用，则按原 section
顺序渲染并记录 warning；只有结果无法渲染时才硬失败。

### Warning And Accept

以下规则只记录 warning，仍返回优化结果：

- 非受保护文本未完全使用英文；
- section label 不理想、重复或不在推荐顺序；
- 主体词、颜色词或引用动作未命中后端关键词表；
- Negative Prompt 启发式判断可能与主体冲突；
- 模型加入非对象数量的构图、镜头、质量或测量参数；
- section 含可清理的轻量 Markdown；
- 动态层级数量偏离 4-10，但内容仍完整可渲染。

warning 只写服务端日志和指标，本次不扩展公开响应，也不增加前端提示。

## 数据流

1. Adapter 解析 Provider JSON，兼容已知字段别名。
2. Normalizer 执行无歧义的结构修复。
3. Validator 生成 `hard_failures` 和 `warnings`，不在每条规则内直接抛异常。
4. 存在 `hard_failures` 时抛出安全的结果校验错误。
5. 仅有 `warnings` 时记录规则代码并返回渲染结果。
6. API 区分供应商失败与结果校验失败，不再统一显示“服务不可用”。

## 代码边界

- `prompt_optimization.py`
  - 负责归一化、校验分级和渲染；
  - 将启发式校验从直接抛异常改为收集 warning。
- `modelark.py`
  - 保留 Provider 解析和已知结构归一化；
  - 不承担业务事实判断。
- `generation.py`
  - 编排解析、归一化、校验和日志；
  - 保留调试埋点直到用户确认修复。
- `aigc_routes.py`
  - 区分 Provider 502 与不安全结果 422。

## 测试

- 单元测试覆盖每条 Hard Fail，确保 BBox、品牌、型号、文案、数量和否定条件仍被保护。
- 单元测试覆盖每条 Auto Repair，确保修复后稳定渲染。
- 参数化测试证明 Warning 规则不会导致请求失败。
- 回归测试覆盖中文首次优化、英文结果再次优化、多次相同请求和随机 section 顺序。
- API 测试验证 Provider 故障返回 502，不安全结果返回 422，warning 结果返回 200。
- 使用当前 pipeline 真实请求连续执行至少 10 次，要求无启发式校验导致的失败。

## 不在范围

- 不改变提示词优化按钮、弹窗或写回交互；
- 不向前端暴露内部 warning；
- 不放宽资产归属、Run 产物、BBox 或引用完整性校验；
- 不改变 LLM 和视频提示词优化契约。
