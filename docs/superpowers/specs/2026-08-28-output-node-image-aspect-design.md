# 图片画布输出节点原图比例适配设计

## 背景

图片画布的输出节点使用固定节点尺寸。标题栏和操作栏占用节点高度后，中间媒体区与原图比例不一致；当前图片尺寸约束在部分布局下未可靠生效，导致缩略图底部内容被裁切。

## 目标

- 输出节点缩略图始终完整显示，不拉伸、不裁切。
- 输出节点在图片加载后，按原图宽高比自动调整媒体区尺寸。
- 文生图、参考图生图、图层拆分三类画布输出统一生效。
- 节点尺寸调整后继续参与现有画布布局持久化。

## 范围

本次仅修改图片画布中的 `OutputNode` 及其页面编排逻辑。资产库、项目列表、预览弹窗等非画布缩略图不在范围内。

## 方案

### 图片渲染

输出节点图片使用占满媒体容器的尺寸约束，并保留 `object-contain`：

- 宽高均占满媒体容器；
- 使用 `object-contain` 保证原图完整显示；
- 媒体区与原图比例一致时不产生明显留白。

### 节点尺寸计算

图片加载成功后，将图片原始宽高回传给画布页面。页面按以下方式计算节点尺寸：

1. 根据原图宽高比，在基准媒体尺寸内约束较长边；
2. 另一边按原图比例计算；
3. 节点总高度等于媒体区高度加固定的标题栏、操作栏和边框占用；
4. 无法读取原始尺寸时保留当前节点尺寸，不阻塞结果展示。

不能直接令整个节点宽高比等于原图宽高比，因为标题栏与操作栏不属于图片媒体区。

### 节点生命周期

- 新建输出节点在任务进行中保持默认尺寸。
- 任务成功并加载图片后自动适配原图比例。
- 从持久化布局恢复的成功输出节点也在图片加载后校正，覆盖此前按固定方形保存的错误尺寸。
- 自动调整通过现有 `scheduleSave` 写回布局。
- 用户后续仍可通过 `NodeResizer` 缩放节点；`object-contain` 始终保证图片完整。

### 覆盖范围

`text_to_image`、`image_to_image`、`layer_decomposition` 三种来源均使用同一 `OutputNode`，因此共享同一图片加载与尺寸适配逻辑。

## 组件改动

- `output-node.tsx`
  - 修正图片尺寸类，保证完整显示。
  - 图片加载后通过画布处理器上报 `naturalWidth` 与 `naturalHeight`。
- `canvas-context.tsx`
  - 增加输出图片加载处理器契约。
- `image-canvas-page.tsx`
  - 增加输出节点尺寸计算函数。
  - 接收图片原始尺寸并更新对应节点尺寸。
  - 调度画布布局保存。

## 验证

- 横图、竖图、方图均按原图比例计算媒体区尺寸。
- 输出节点总高度正确包含标题栏和操作栏。
- 图片原始尺寸不可用时保持当前尺寸。
- 三种输出来源共用同一适配行为。
- 缩略图使用 `object-contain` 且完整显示。
- 前端 lint、typecheck 与相关 Vitest 测试通过。
