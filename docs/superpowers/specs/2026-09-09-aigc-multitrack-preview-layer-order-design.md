# AIGC 多轨预览层级修复设计

## 问题

多轨时间线将配置数组反向展示，使较大的 `track.order` 显示在更靠上的位置。画面预览当前却使用数组反向索引计算 `z-index`，导致底部视频轨道覆盖上方文字或图片轨道。元素已进入有效时间范围且正常渲染到 DOM，但视觉上不可见。

## 方案

采用方案 A：预览层直接按轨道顺序计算层级。

- 先按 `track.order` 判断叠放关系，不依赖配置数组当前排列。
- `track.order` 越大，预览层的 `z-index` 越大，与时间线顶部轨道处于视觉上层的规则一致。
- 当历史数据存在重复 `order` 时，使用原数组索引稳定消歧，避免层级闪烁。
- 不修改轨道数组、不强制文字或图片覆盖其他类型，也不改变保存数据和 MediaKit 请求。

## 影响范围

- 修改 `getPreviewVisualLayers` 的层级计算。
- 保持播放头过滤、隐藏轨道过滤和音频/字幕排除逻辑不变。
- 保持视频当前帧、文字/图片拖拽缩放和撤销逻辑不变。

## 验证

- 单元测试验证视频轨道 `order=0`、文字轨道 `order=1` 时文字层级更高。
- 单元测试验证配置数组顺序变化不影响由 `track.order` 决定的层级。
- 组件测试验证文字元素不只存在于 DOM，还具有高于背景视频的实际层级。
- 运行相关 Vitest、TypeScript、ESLint 和多视口 Playwright 验收。
