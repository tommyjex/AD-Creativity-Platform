# AIGC Multi-Track Upstream Text Preview Design

## Goal

Render the actual value of an upstream text source in the multi-track canvas,
timeline clip, and inspector instead of the generic `上游文字` placeholder.

## Source Semantics

An upstream-bound text element keeps:

```ts
source: {
  source_node_id: string;
  source_handle: string;
}
```

The preview value is transient editor context. It must not be copied into
`inline_text` or persisted into the Pipeline definition. MediaKit execution
continues to resolve the upstream value from the executing Run on the backend.

## Resolution Order

For each direct text source connected to the multi-track node:

1. Use the text result from the newest successful Run whose projection scope
   contains that source node.
2. If no successful result exists and the source is a static `text` node, use
   its current configured text.
3. Otherwise show `等待上游运行`.

A text node is static only when it has no incoming text connection and was not
generated by a JSON Parser. A failed or timed-out Run lookup degrades to the
static fallback or waiting state; it never blocks the timeline editor.

## Data Model

`AigcTimelineSource` gains editor-only fields:

```ts
preview_text?: string | null;
text_preview_status?: "resolved" | "configured" | "unavailable";
```

These fields exist only in the timeline page state and are excluded from
`MultiTrackSource`, saved config, hashes, and Provider payloads.

## Loader

`loadAigcTimelineEditorData` continues to load the Pipeline and media metadata.
For text sources it additionally:

1. lists Runs newest first;
2. inspects successful Run scopes using existing branch-projection rules;
3. fetches only Run details that may resolve an unresolved text source;
4. records the first successful, non-empty text result for each source;
5. applies the static fallback after Run lookup completes.

Run detail requests use a bounded timeout. Duplicate source references and
multiple sources covered by one Run share the same fetched detail.

## Presentation

A single pure resolver returns display text for a text element:

- inline element: trimmed `inline_text`;
- upstream element with preview: `preview_text`;
- unresolved upstream element: `等待上游运行`.

The same resolver is used by:

- the canvas text layer;
- the timeline clip label;
- the element inspector.

For an upstream-bound element, the inspector displays a read-only text area
and a `转为内联文字` command. Conversion copies the current preview text,
clears `source`, and creates one history entry. Conversion is disabled while
the source is unresolved.

## Error Handling

- Pipeline loading errors keep their existing blocking behavior.
- Run list/detail errors are caught and converted to fallback display state.
- Empty Run text is treated as unavailable.
- A stale Run never mutates the saved draft.

## Validation

Tests cover:

- newest successful Run selection;
- branch-specific Run projection;
- static text fallback;
- dynamic-source waiting state;
- Run API failure fallback;
- consistent canvas, timeline, and inspector text;
- explicit conversion to inline text and undo;
- no preview fields in saved config;
- desktop, tablet, and mobile acceptance without real Provider calls.
