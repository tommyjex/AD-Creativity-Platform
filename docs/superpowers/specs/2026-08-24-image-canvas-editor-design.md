# 图片画布编辑器设计

## 目标

将图片项目的单图精准编辑与多参考图对象替换收敛为画布优先的编辑工作区。用户在一个全屏编辑器内选择目标图、参考图和区域，输入指令后生成新的公共图片版本。

保持既有图片版本、任务冻结、失败重试、资产隔离、提示词版本和图层集合 revision 语义不变。

## 已确认布局

采用方案 A「双栏工作台」：

- 桌面端左侧为目标图画布、模式工具条和参考图缩略图区。
- 右侧为固定指令栏，包含模式、编辑指令、不可编辑的区域引用、输入校验提示和生成操作。
- 目标图为图 1；已选择的项目参考图按显示顺序编号为图 2 至图 11。
- 移动端保持画布在前，参考图和指令栏在下方堆叠；指令栏可以折叠，但生成操作必须保持可访问。
- 图片卡片的“编辑”入口打开全屏 Dialog，并将该图片预选为目标图。

固定侧栏优先于浮层工具：框选、参考图选择和任务校验属于连续工作流，常驻信息能避免画布被浮层遮挡，也为后续图层保存和冲突状态预留稳定位置。

## 组件边界

新增 `ImageCanvasEditor`，由 `ImageProjectWorkspace` 控制打开状态、活动任务、版本刷新与全局反馈。

`ImageCanvasEditor` 的输入：

- 目标资产候选（公共 `generated_image`）。
- 已持久化的项目参考图（最多 10 张）。
- 输出尺寸、格式和提交状态。
- 关闭与提交回调。

组件内部仅保存临时编辑状态：

- `mode`: `single_edit` 或 `reference_replace`。
- `targetAssetId`。
- `targetBbox`。
- 每张参考图的 `referenceBbox`。
- 编辑指令。

几何计算复用现有 `getContainedImageRect`、`normalizeImagePoint` 和 bbox 创建逻辑；如提取为共享工具，行为及归一化范围保持 `0..999`。框选通过指针事件完成，拖动创建、清除和重选区域均不写入后端。

原 `ImageEditDialog` 不再作为主要入口。为降低回归风险，在画布编辑器稳定前可保留其组件和 API 提交兼容性，但图片卡片不再打开它。

## 模式与提交映射

### 单图编辑

单图编辑要求：

- 已选择目标图。
- 存在合法目标 bbox。
- 编辑指令非空。

提交请求：

```json
{
  "operation": "image_to_image",
  "source_asset_id": "target-asset-id",
  "prompt": "用户编辑指令",
  "annotation": {
    "type": "bbox",
    "x1": 100,
    "y1": 200,
    "x2": 800,
    "y2": 900
  },
  "size": "2K",
  "format": "png"
}
```

现有服务继续根据 `annotation` 生成带图 1 bbox 的最终提示词，作为冻结输入的一部分。

### 参考图对象替换

参考图替换要求：

- 已选择目标图和至少一张参考图。
- 目标图存在合法 bbox。
- 每张已选参考图都存在合法 bbox。
- 编辑指令非空。

提交请求：

```json
{
  "operation": "image_to_image",
  "source_asset_id": "target-asset-id",
  "prompt": "将图 3 的主体替换到目标区域",
  "edit_mode": "reference_replace",
  "target_bbox": {
    "type": "bbox",
    "x1": 100,
    "y1": 200,
    "x2": 800,
    "y2": 900
  },
  "reference_regions": [
    {
      "asset_id": "reference-asset-id",
      "image_index": 3,
      "bbox": {
        "type": "bbox",
        "x1": 120,
        "y1": 160,
        "x2": 760,
        "y2": 900
      }
    }
  ],
  "size": "2K",
  "format": "png"
}
```

右栏展示由临时结构化状态派生的图号与 bbox 引用，不能编辑。客户端不生成或信任用户输入的 bbox 标签；后端继续校验资产、顺序、图片编号和区域，并负责冻结、最终提示词编译、重试和产物 metadata。

切换模式时，不适用于当前模式的临时框选不参与提交。切换回原模式可保留临时框选，直到用户明确清除、改变目标图或关闭编辑器。

## 任务与错误状态

`ImageProjectWorkspace` 继续负责提交后的轮询：

- 任务成功：刷新项目和图片版本区，显示新图片版本可用。
- 任务失败：显示后端脱敏错误，保留画布的临时选择与指令，允许用户修正后重新提交。
- 提交进行中：禁用关闭、切换目标图、上传参考图和重复生成。

生成按钮旁显示可恢复的校验原因：

- 未选择目标图。
- 未框选目标区域。
- 参考图替换模式下未选择参考图。
- 存在未框选区域的参考图。
- 未输入编辑指令。

参考图上传和选择仍使用现有持久化选择接口。上传中或生成中禁止新增、移除或重排参考图。

## 图层整合边界

图层拆分与直接编辑嵌入现有 `LayerEditorDialog`：

- 图层模式复用现有 `LayerEditorDialog` 的移动、等比缩放、显隐、排序、保存和 revision 冲突行为。
- 底图仍不可变换或内容编辑。
- 右侧图层面板为选中的非底图显示编辑指令和“生成替换图层”操作。
- 提交时创建图层内容编辑任务，冻结图层集合 ID、预期 revision、图层 ID、源内部资产 ID/对象键/创建时间、指令和输出参数。
- Seedream 使用冻结的内部图层资产作为源图生成替换内容。成功结果以新的 `internal_layer` 资产存储，metadata 记录 `replaced_layer_asset_id`、图层集合 ID、图层 ID、编辑任务 ID 和最终指令。
- 后端以冻结的 `expected_revision` 原子更新目标图层的 `asset_id` 并递增集合 revision。旧内部资产不删除，仍可由冻结输入和新资产 metadata 追溯。
- 若集合 revision 已变化，成功生成的替换资产不覆盖远端图层；任务失败并返回冲突提示。用户刷新集合后可再次发起编辑。
- 图层内容编辑进行中禁用该图层的重复提交，但不改变其他既有图层变换语义。

不直接覆盖旧图层资产的对象或数据库记录，以保证任务重试、审计和已经冻结的图层导出可复现。

## 测试与验收

前端测试覆盖：

- 从图片卡片打开画布并预选目标图。
- 单图/参考图替换模式切换、禁用状态和区域引用。
- pointer 坐标转换、清除和重新框选。
- 参考图顺序与 `image_index`、请求体的一致性。
- 成功轮询后刷新版本；失败后保留草稿。
- 图层编辑任务冻结、内部替换资产 metadata、revision 原子更新和冲突不覆盖。
- 非底图内容编辑入口与底图禁用状态。
- 桌面和 390px 视口下无横向溢出、控件重叠或不可访问操作。

后端回归覆盖已有多参考图 schema、冻结输入、提示词编译、Seedream 多图参数、资产校验和失败重试。

验证命令：

```bash
.venv/bin/pytest backend/tests/test_image_generation.py backend/tests/test_project_types.py
cd frontend && npm run lint && npm run typecheck && npm test -- image-project-workspace.test.tsx
```

## 非目标

- 本阶段不更改图片生成模型、任务冻结格式或资产访问策略。
- 不支持自由绘制、多边形选区、蒙版或手动输入坐标。
