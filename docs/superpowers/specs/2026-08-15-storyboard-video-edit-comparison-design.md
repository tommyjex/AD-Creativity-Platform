# 分镜视频编辑与双栏同步对比设计

## 背景

当前分镜视频工作台支持生成、重新生成和删除视频。重新生成会直接更新当前分镜视频，
用户无法基于现有视频提交定向编辑指令，也无法在替换前对照原版与编辑版。

本次增加“编辑视频”流程：以当前分镜视频为源素材生成一个独立候选，生成完成后通过
双栏同步播放对比原版和候选，用户显式选择最终保留版本。

## 目标

1. 已生成视频的分镜可提交文本编辑指令。
2. 编辑任务生成独立候选，确认前不修改 `StoryboardShot.video_asset_id`。
3. 原版与编辑版在同一弹窗左右常驻，并共享播放、暂停、进度和静音状态。
4. 用户可返回修改编辑指令、保留原版或保留编辑后版本。
5. 被替换的原版和未采用的编辑结果继续保留在资产库，避免破坏历史产物。

## 非目标

- 不提供逐帧剪辑、裁切、拼接或时间线轨道。
- 不实现画面擦除滑杆或标签切换对比。
- 不删除未被分镜采用的视频资产。
- 不增加数据库版本表或完整版本树。
- 不把重新生成流程改为候选确认流程。

## 用户流程

### 发起编辑

仅当当前分镜已有可访问的成功视频资产时显示“编辑视频”按钮。

点击后打开编辑指令弹窗：

- 展示当前视频缩略预览。
- 提供必填多行编辑指令，限制 4000 字符。
- 提交后创建视频编辑任务。
- 任务进行时显示进度，禁止重复提交。
- 用户可以关闭任务状态弹窗；后台轮询继续沿用工作台任务机制。

编辑请求将当前视频作为源参考，并明确要求模型在保持原时长、画幅、人物、主体和动作
连续性的基础上执行编辑指令。

### 双栏同步对比

编辑任务成功后自动打开对比弹窗：

- 左侧固定为发起编辑时的原始视频。
- 右侧固定为本次编辑生成的候选视频。
- 两侧使用相同画幅容器，各自完整展示构图。
- 顶部展示镜头信息和本次编辑指令。
- 底部只有一套播放、进度、时间、静音和全屏控制。

对比弹窗提供三个命令：

- `返回调整`：保留候选资产但关闭对比，重新打开编辑指令弹窗。
- `保留原版`：不修改分镜关联并关闭流程。
- `保留编辑后版本`：将分镜的 `video_asset_id` 切换到候选资产。

关闭对比弹窗等同于放弃本次候选关联，不修改当前分镜视频。候选仍作为视频编辑产物
保留在资产库。

## 同步播放规则

对比播放器由一个控制器管理两个原生 `<video>` 元素：

1. 播放前把两侧定位到统一时间。
2. 任一侧尚未可播放时，两侧都保持暂停。
3. 播放中以原版为主时钟；时间偏差超过 120ms 时校正候选时间。
4. 拖动进度时先暂停两侧，完成 seek 后再恢复原播放状态。
5. 任一侧发生等待或卡顿时暂停另一侧；两侧均可播放后恢复。
6. 静音和音量同时应用到两侧，但默认只输出编辑后版本的音频，避免双重声音。
7. 对比总时长取两侧较短值；编辑服务应尽量保持与原版时长一致。
8. 组件卸载、切换候选或关闭弹窗时移除事件监听并暂停媒体。

全屏作用于整个双栏对比区域，而不是单个视频。

## 后端设计

### 请求与响应

新增：

```text
POST /api/projects/{project_id}/storyboard/shots/{shot_id}/edit-video
Content-Type: application/json

{"prompt": "增强产品特写，保持人物动作连续"}
```

返回现有 `GenerationTask`。任务成功后的 `output_asset_ids` 包含唯一候选视频资产 ID。

新增：

```text
POST /api/projects/{project_id}/storyboard/shots/{shot_id}/select-video
Content-Type: application/json

{"asset_id": "候选视频资产 ID"}
```

返回更新后的 `StoryboardShotVideoConfig`。

`select-video` 校验：

- 分镜属于当前项目。
- 资产属于当前项目。
- 资产类型为 `storyboard_video`，状态为 `succeeded`。
- 候选 metadata 的 `source_shot_id` 与当前分镜一致。
- 候选 metadata 的 `operation` 为 `video_edit`。

选择原版不需要请求后端，因为分镜关联未发生变化。

### ModelArk 适配

新增 `VideoEditRequest` 和 `edit_video()`：

- 文本内容由稳定约束、本次编辑指令和原视频上下文组成。
- 源视频以 `video_url` 内容和 `reference_video` 角色提交。
- 沿用当前视频模型、720p、音频生成、尾帧返回和轮询机制。
- 时长取原视频 metadata 中的时长；缺失时回退到分镜时长。
- 画幅沿用项目画幅。

编辑结果仍使用 `AssetType.STORYBOARD_VIDEO` 和 `Stage.VIDEO`，metadata 增加：

```text
operation=video_edit
source_asset_id=<原版资产 ID>
source_shot_id=<分镜 ID>
edit_prompt=<用户指令>
```

提供方不支持源视频编辑或返回失败时，任务失败，不创建候选，也不修改分镜关联。

### 任务与资产

生成服务新增独立的视频编辑方法，复用现有远程资产下载、对象存储上传和任务错误清洗。
编辑任务完成后只写 `output_asset_ids`，不调用 `set_storyboard_shot_video_asset`。

确认候选时只更新 `video_asset_id`。原版资产和候选资产均不删除；工作流下游失效规则与
现有分镜视频替换保持一致。

Memory 与 MySQL 仓库必须实现相同的候选校验和关联更新语义。

## 前端设计

### 状态

`StoryboardVideoWorkspace` 增加：

- 编辑指令弹窗状态与草稿。
- 当前编辑任务。
- 对比上下文：原版资产 ID、候选资产 ID、编辑指令。
- 候选确认 loading 与错误状态。

原版资产 ID 在发起编辑时固定保存。即使项目刷新，也不能用新的
`video_asset_id` 覆盖本轮对比左侧来源。

### 组件

新增局部组件：

- `StoryboardVideoEditDialog`：编辑指令和任务状态。
- `StoryboardVideoComparisonDialog`：双栏布局和版本选择。
- `SynchronizedVideoComparison`：封装双视频时钟、缓冲和媒体控制。

播放器控制逻辑独立成 hook 或组件，避免继续扩张
`storyboard-video-workspace.tsx` 的职责。

### 数据刷新

1. 提交编辑请求后记录原版 ID并轮询任务。
2. 成功后刷新项目资产，解析任务唯一输出资产。
3. 原版与候选均具备安全预览 URL后打开对比弹窗。
4. 选择编辑版后调用 `select-video`，更新配置、镜头和父项目。
5. 刷新失败时保留任务结果和资产 ID，提供重试，不自动替换当前视频。

## 错误处理

- 当前视频不可访问：禁用编辑并显示原因。
- 编辑指令为空或过长：前端阻止提交，后端返回 422。
- 编辑任务失败：保留指令，显示安全的提供方错误摘要，可重试。
- 候选输出缺失或多于一个：视为任务结果无效，不进入对比。
- 任一对比视频加载失败：停止同步播放，显示对应侧错误和重试入口。
- 确认候选失败：保持对比弹窗和当前分镜关联不变，可重试。
- 候选已被删除或不属于当前分镜：后端拒绝关联。

## 测试

### 后端

- `VideoEditRequest` 校验空指令和长度。
- ModelArk 编辑请求包含文本与源视频引用，并保持时长、画幅和音频参数。
- 编辑任务成功创建带来源 metadata 的独立候选。
- 编辑任务不提前替换 `video_asset_id`。
- `select-video` 接受合法候选并拒绝跨项目、跨分镜、错误类型和失败资产。
- Memory/MySQL 行为一致。
- 提供方失败时任务失败且当前分镜不变。

### 前端

- 只有存在成功视频时显示编辑入口。
- 提交编辑指令调用正确接口并轮询任务。
- 成功后左右侧使用固定原版和任务候选。
- 播放、暂停、seek、静音和缓冲状态同步。
- 时间漂移超过阈值时校正候选。
- 保留原版和关闭弹窗不调用选择接口。
- 保留编辑版成功后更新当前预览。
- 返回调整恢复本次编辑指令。
- 加载、任务、候选刷新和确认失败均保留可恢复状态。

```bash
.venv/bin/python -m pytest backend/tests/
cd frontend && npm test
cd frontend && npm run typecheck
cd frontend && npm run lint
```

## 验收标准

1. 编辑候选生成期间和确认前，当前分镜视频不发生变化。
2. 双栏能同时完整显示原版和编辑版，并通过一套控件同步播放。
3. 正常播放时两侧可见时间差不超过 120ms。
4. 卡顿、seek 和关闭弹窗不会导致单侧继续播放。
5. 只有显式选择编辑版才更新 `video_asset_id`。
6. 原版和未采用候选均可在资产库继续访问。
7. 前后端新增测试及现有回归测试通过。
