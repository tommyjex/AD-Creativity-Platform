# 多参考图提示词优化类型判定设计

## 问题

`image_to_image` 节点存在多张参考图时，前端会正确提交
`reference_image_count > 0`，但不会提交只适用于单一可验证源图的
`source_image_url`。当前后端仅依据 `source_image_url` 判断允许的
Seedream 生图类型，导致模型正确返回“参考图生图”后仍被判为不兼容并返回
HTTP 502。

## 设计

新增一个纯函数，统一根据请求语义和源图可用性返回允许的生图类型：

- `text_to_image`：仅允许“文生图”。
- `image_to_image` 且存在可用单一源图：允许“图像编辑”或“参考图生图”。
- `image_to_image`、无单一源图但 `reference_image_count > 0`：允许“参考图生图”。
- `image_to_image` 且没有任何参考图：仅允许“文生图”。

模型适配层和生成服务层共同调用该函数，避免两份条件再次漂移。保留现有严格
输出格式校验、安全约束和错误映射。

## 验证

- 单元测试覆盖多参考图、单源图、无参考图和文生图四类判定。
- 复用真实“哈吉斯西装”Pipeline 请求，比较修复前后的调试日志和 HTTP 响应。
- 运行提示词优化相关测试、后端完整测试。
