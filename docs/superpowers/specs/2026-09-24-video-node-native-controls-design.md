# 画布视频节点原生控件保护设计

## 背景

画布视频节点通过透明交互层实现画面拖拽和双击播放。当前交互层仅在底部预留 48px，实际覆盖了 Chromium 原生播放器的播放、音量、全屏、更多菜单和进度条，导致这些功能无法使用。

## 目标

- 视频上半区继续支持拖拽节点。
- 视频上半区继续支持双击播放或恢复播放。
- 视频下半区完全交给浏览器原生播放器。
- 播放/暂停、音量、全屏、更多菜单和进度条不得被透明层遮挡。
- 不查询、修改或依赖浏览器私有的原生控件 DOM。

## 设计

### 交互区域

节点模式下，透明交互层只覆盖视频可视区域的上半区：

- 上半区：React Flow 节点拖拽、双击调用 `video.play()`。
- 下半区：直接命中 `<video controls>`，由浏览器处理全部原生功能。
- 触摸设备：继续禁用透明交互层，直接使用原生播放器。

面板模式不渲染透明交互层，保持现有行为。

### 事件优先级

1. 视频下半区的原生控件拥有最高优先级，不触发节点拖拽、画布平移或双击动作。
2. 视频上半区超过拖拽阈值时仅移动节点，不触发播放。
3. 视频上半区未形成拖拽的双击调用 `play()`，不暂停、不重置播放进度。
4. `play()` Promise 被拒绝时静默保持当前播放器状态。

### 实现范围

- 调整 `AigcVideoPlayer` 透明交互层的 CSS 边界，由固定底部预留改为只覆盖上半区。
- 更新组件测试，验证交互层边界和原生播放器事件隔离。
- 使用 Chromium 真实验收下半区播放、音量、全屏、更多菜单与进度条命中。

## 验收标准

- 上半区可拖动视频节点，拖动后不播放。
- 上半区双击从当前位置播放或恢复播放。
- 下半区播放/暂停按钮可点击。
- 下半区音量控件可操作。
- 下半区全屏按钮可操作。
- 下半区更多菜单可打开。
- 进度条可拖动。
- 操作上述原生控件时节点位置不变化。
- 桌面、平板和手机视口无新增遮挡或溢出。

## 非目标

- 不实现自定义播放器控件。
- 不改变视频 URL、媒体加载或下载逻辑。
- 不修改画布坐标和自动保存协议。
- 不依赖 Chromium Shadow DOM 的内部结构。
