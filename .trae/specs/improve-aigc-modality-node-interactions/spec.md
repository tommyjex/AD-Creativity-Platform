# 优化 AIGC 模态节点直接交互 Spec

## Why

AIGC 无限画布中的图片、视频和文本节点虽然已支持从部分非交互区域拖拽，但核心内容区仍被单击预览、原生播放器或检查器入口割裂。用户需要在默认鼠标状态下直接拖动节点，并通过双击内容进入对应的放大查看、播放或提示词编辑流程。

## What Changes

- 图片节点取消“单击图片打开预览”，图片内容区改为可直接拖拽；双击图片打开既有原图放大 Dialog。
- 视频节点的画面区域支持直接拖拽；双击视频画面开始或恢复播放，原生播放按钮、进度、音量和全屏控件继续可用。
- 文本节点的文本内容区支持直接拖拽；双击文本打开既有全屏提示词编辑器。
- 统一单击、拖拽和双击的优先级，避免拖动结束误触发放大、播放或编辑。
- 保留按钮、端口、原生媒体控制条、输入框及其它明确交互控件的 `nodrag`/事件隔离。
- 不新增鼠标工具模式、拖拽把手、后端接口或持久化字段。

## Impact

- Affected specs:
  - 模态节点拖拽与图片操作图标优化
  - AIGC 全屏提示词编辑器
  - AIGC 视频输出全屏与原生控制
- Affected code:
  - `frontend/components/workspace/aigc/aigc-editor.tsx`
  - `frontend/components/workspace/aigc/aigc-flow-node.tsx`
  - `frontend/components/workspace/aigc/aigc-video-player.tsx`
  - `frontend/components/workspace/aigc/aigc-prompt-editor.tsx`
  - `frontend/components/workspace/aigc/aigc-node-interaction-context.tsx`
  - 对应 Vitest 与 Playwright 验收脚本
- Unaffected:
  - Pipeline definition、节点坐标和自动保存数据结构
  - 资产预览、下载和运行结果投影契约
  - 后端 API 与数据库
  - 音频节点及模型/控制类节点

## ADDED Requirements

### Requirement: 默认鼠标状态下直接拖动模态节点

系统 SHALL 在不切换工具、不按修饰键且不使用专用拖拽把手的情况下，允许用户从图片、视频和文本节点的任意非交互内容区域按下并拖动节点。

“任意位置”在本 Spec 中指节点卡片内不承担独立命令的区域。端口、按钮、链接、输入框、视频原生控制条以及其它明确交互控件 SHALL 保持自身操作优先，不得启动节点拖拽。

#### Scenario: 从图片内容区拖动

- **WHEN** 用户在图片画面上按下鼠标并移动超过 React Flow 的拖拽阈值
- **THEN** 图片节点跟随指针移动
- **AND** 松开后通过既有 `onNodeDragStop` 和自动保存链路持久化新坐标
- **AND** 不打开图片放大预览

#### Scenario: 从视频画面拖动

- **WHEN** 用户在视频画面区域按下鼠标并移动，且起点不位于原生控制条
- **THEN** 视频节点跟随指针移动
- **AND** 不改变播放状态或进入全屏

#### Scenario: 从文本内容区拖动

- **WHEN** 用户在文本摘要或其空白区域按下鼠标并移动
- **THEN** 文本节点跟随指针移动
- **AND** 不打开提示词编辑器

#### Scenario: 操作交互控件

- **WHEN** 用户操作图片精准编辑按钮、节点端口、文本复制按钮、输入框或视频原生控制条
- **THEN** 对应控件执行原有功能
- **AND** 节点位置不发生变化

#### Scenario: 单击但不拖动

- **WHEN** 用户在可拖拽内容区单击并在拖拽阈值内释放
- **THEN** 节点按既有行为被选中并打开对应检查器
- **AND** 不触发图片放大、视频播放或文本全屏编辑

### Requirement: 图片节点双击放大

图片节点 SHALL 将图片画面作为可拖拽内容区，并仅在有效图片上收到双击时打开既有原图预览 Dialog。

#### Scenario: 双击有效图片

- **WHEN** 用户双击图片节点中的有效图片画面，且两次点击之间没有形成拖拽
- **THEN** 打开既有“查看原图”Dialog
- **AND** Dialog 中图片使用 `object-contain` 保持原始宽高比，不裁切、不拉伸
- **AND** 双击事件不触发 React Flow 画布缩放

#### Scenario: 单击有效图片

- **WHEN** 用户仅单击图片画面
- **THEN** 不打开原图 Dialog
- **AND** 图片画面仍可作为拖拽起点

#### Scenario: 图片不可用

- **WHEN** 图片节点没有可用预览 URL 或图片加载失败
- **THEN** 双击占位区域不打开空 Dialog
- **AND** 节点仍可从占位区域拖动

#### Scenario: 键盘访问图片预览

- **WHEN** 键盘用户聚焦图片预览入口并按下 Enter
- **THEN** 打开与鼠标双击相同的原图 Dialog

### Requirement: 视频节点双击播放

视频节点 SHALL 在保留浏览器原生播放器控制条的同时，使视频画面承担节点拖拽和双击播放操作。
在精确指针设备上，组件 SHALL 使用独立的透明画面交互层覆盖视频可视区域，并为底部原生控制区域保留直接命中空间；该交互层不得查询、修改或模拟浏览器私有的原生控制 DOM。触摸设备不强制提供双击手势，继续直接使用原生播放器和节点其它拖拽区域。

#### Scenario: 双击暂停或待播放的视频画面

- **WHEN** 用户双击视频画面，且视频 URL 可用
- **THEN** 系统调用该视频元素的 `play()`
- **AND** 视频从当前位置开始或恢复播放
- **AND** 不打开新的预览 Dialog，不重置播放进度
- **AND** 双击事件不触发画布缩放

#### Scenario: 双击正在播放的视频画面

- **WHEN** 用户双击已经播放中的视频画面
- **THEN** 视频继续播放
- **AND** 不重置进度、不切换暂停状态

#### Scenario: 点击原生播放按钮

- **WHEN** 用户点击浏览器原生播放器的播放或暂停按钮
- **THEN** 播放器按浏览器原生语义播放或暂停
- **AND** 节点不移动
- **AND** 不触发画布选择、缩放或双击动作

#### Scenario: 操作其它原生控件

- **WHEN** 用户拖动进度、调整音量或切换原生全屏
- **THEN** 原有播放器行为保持可用
- **AND** 节点不移动

#### Scenario: 视频不可用或播放失败

- **WHEN** 视频 URL 不可用，或 `play()` Promise 被浏览器拒绝
- **THEN** 不抛出未处理异常
- **AND** 保持既有不可用状态或播放器状态
- **AND** 节点仍可从非控件区域拖动

### Requirement: 文本节点双击打开全屏提示词编辑器

文本节点 SHALL 在用户双击文本摘要区域时，通过画布级交互协调器打开该节点对应的既有全屏提示词编辑器。

#### Scenario: 双击本地文本节点

- **WHEN** 用户双击本地模式文本节点的文本摘要，且未形成拖拽
- **THEN** 当前节点被选中
- **AND** 打开该节点的全屏提示词编辑器
- **AND** 编辑器草稿初始化为当前有效文本

#### Scenario: 双击可覆盖的上游文本节点

- **WHEN** 用户双击具有可用上游文本、且允许节点级覆盖的文本节点
- **THEN** 全屏编辑器显示当前 Run 的有效文本或已有 override
- **AND** 应用后继续使用既有 override、撤销和自动保存语义

#### Scenario: 双击只读托管文本

- **WHEN** 用户双击由 JSON Parser 等托管来源提供的只读文本节点
- **THEN** 打开既有只读全屏预览
- **AND** 不显示应用操作，不允许写回文本

#### Scenario: 取消或关闭编辑器

- **WHEN** 用户按 Escape、点击关闭或取消
- **THEN** 丢弃未应用草稿
- **AND** 焦点返回触发双击的文本节点内容区

#### Scenario: 键盘访问文本编辑器

- **WHEN** 键盘用户聚焦文本内容区并按下 Enter
- **THEN** 打开与鼠标双击相同的全屏提示词编辑器

### Requirement: 画布级交互协调

系统 SHALL 使用单一的画布级临时交互状态协调文本全屏编辑请求，避免在每个文本节点中复制完整编辑器 Dialog 或把打开状态写入 Pipeline definition。

#### Scenario: 快速切换目标节点

- **WHEN** 用户关闭一个文本编辑器后双击另一个文本节点
- **THEN** 编辑器只绑定最新目标节点
- **AND** 不残留前一节点的草稿、Run 投影、校验错误或焦点引用

#### Scenario: 目标节点被删除

- **WHEN** 全屏编辑器打开期间目标文本节点被删除或不再存在
- **THEN** 编辑器安全关闭
- **AND** 不写入其它节点

#### Scenario: 编辑器已经打开

- **WHEN** 用户对同一文本节点重复触发打开请求
- **THEN** 系统保持单个 Dialog 实例
- **AND** 不重置用户尚未应用的当前草稿

## MODIFIED Requirements

### Requirement: 模态节点拖拽边界

图片、视频、文本和音频模态节点 SHALL 继续支持从非交互区域直接拖动。本次将图片画面、视频画面和文本摘要纳入拖拽区域；图片精准编辑按钮、节点操作按钮、文本复制按钮、连接端口及视频原生控制条继续隔离拖拽。音频节点行为保持不变。

#### Scenario: 拖动与双击竞争

- **WHEN** 指针序列被 React Flow 判定为节点拖拽
- **THEN** 该序列不得继续触发图片放大、视频播放或文本编辑

- **WHEN** 指针没有超过拖拽阈值并形成双击
- **THEN** 才执行对应节点的双击动作

### Requirement: AIGC 全屏提示词编辑器入口

全屏提示词编辑器 SHALL 同时支持右侧检查器入口和画布文本节点双击入口。两个入口共享同一个编辑器实例、有效文本解析、只读判断、草稿隔离、优化提示词、应用、取消、并发保护、焦点恢复和自动保存语义。

#### Scenario: 从任一入口打开

- **WHEN** 用户从右侧检查器按钮、检查器文本预览或画布文本节点打开编辑器
- **THEN** 三种入口显示同一个目标节点和相同有效文本
- **AND** 应用结果一致地写回该节点

## REMOVED Requirements

### Requirement: 单击图片画面打开原图

**Reason**: 单击行为与“按下后直接拖拽节点”竞争，导致图片成为不可用的拖拽死区。

**Migration**: 图片放大改为双击；键盘用户仍可通过聚焦图片预览入口并按 Enter 打开。

## Non-Functional Requirements

- 节点拖动和双击不得新增后端请求。
- 双击动作不得修改节点位置、尺寸或 Pipeline definition。
- 拖动结束只沿用现有坐标保存链路，不产生额外历史记录。
- 图片和视频继续使用固定媒体区与 `object-contain`，保持原始宽高比。
- 事件处理不得依赖浏览器私有的原生控制条 DOM。
- 桌面、平板和手机视口均不得出现控件遮挡或布局位移；鼠标双击仅作为桌面交互要求，触摸端继续使用原生控件和既有显式入口。
- 组件卸载、节点切换和 Dialog 关闭后不得残留全局事件监听器。
