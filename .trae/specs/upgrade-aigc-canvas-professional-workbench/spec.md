# AIGC 画布专业工作台布局 Spec

## Why

当前 AIGC 编辑器在桌面端同时常驻 `240px` 节点库和 `288px` 检查器。在 1024px 至 1440px 的常见窗口中，两侧面板会持续占用 528px，使画布、复杂节点和连线的可视区域不足。顶部命令、React Flow 控件和移动端面板入口也分散在不同位置，画布缺少清晰的“创作区优先”层级。

本变更采用已确认的 B 方案“专业工作台混合式”：保留高频节点库，但压缩为窄栏；右侧详情按需展开；全局命令位于顶部；画布导航工具收敛到底部。目标是在不改变节点、运行、自动保存和后端契约的前提下扩大有效画布面积，并保持复杂配置与运行日志可达。

## What Changes

- 桌面端节点库收窄为固定 `184px`，保留分类、模态色图标和完整节点名称。
- 右侧详情栏改为按需展开的固定 `320px` 面板，默认收起；选中节点时打开“配置”，打开运行记录时切到“运行”。
- 顶部栏增加详情栏与运行记录入口，并继续承载返回、标题、自动保存状态、撤销、重做、另存模板和执行。
- React Flow 的缩放、适配视图和交互锁定控件移动到画布底部中央，形成稳定工具坞。
- 小于 `1024px` 时，节点库和详情栏继续作为覆盖画布的互斥浮层；命令保持可达，画布不设置水平边界。
- 保留现有节点渲染、拖拽缩放、连线校验、运行投影、自动保存、`flush()`、409 冲突保护和模板模式行为。
- 不新增后端 API、数据库字段或画布 definition 字段；面板开合属于本地临时 UI 状态，不触发自动保存。

## Impact

- Affected specs:
  - AIGC 画布交互布局
  - 自动保存状态与命令前 `flush()`
  - 运行历史与节点检查器
- Affected code:
  - `frontend/components/workspace/aigc/aigc-editor.tsx`
  - `frontend/components/workspace/canvas/node-canvas.tsx`
  - `frontend/tests/aigc-editor.test.tsx`
  - 如共享画布控件契约需要独立测试：`frontend/tests/node-canvas.test.tsx`
- Backend API、数据库结构、AIGC DTO 和 Pipeline definition 不变。

## Design Decision

- **采用：窄节点库 + 按需停靠详情栏。** 高频添加节点仍是一跳操作，关闭详情栏时比现状多获得 `344px` 画布宽度；需要配置或查看运行时再使用完整宽度面板。
- 未采用“移除全部常驻侧栏”：虽然画布面积最大，但节点发现成本和学习成本明显增加。
- 未采用“节点旁内联 Prompt 编辑”：复杂配置、运行日志和结果预览需要更稳定的空间，内联浮层还会遮挡连线与相邻节点。
- 不持久化面板开合状态：它不属于 Pipeline 业务定义，刷新后回到稳定默认布局即可。
- 不新增自由拖拽面板宽度：固定尺寸便于控制画布面积、响应式行为和测试范围。

## ADDED Requirements

### Requirement: 桌面专业工作台骨架

系统 SHALL 在宽度不小于 `1024px` 的编辑器中使用顶部命令栏、左侧窄节点库、中央画布、按需右侧详情栏和底部画布工具坞组成工作台。

#### Scenario: 默认进入桌面画布

- **WHEN** 用户在桌面窗口打开 Pipeline 或模板编辑器
- **THEN** 顶部命令栏和 `184px` 节点库可见
- **AND** 右侧详情栏默认收起
- **AND** 中央画布占用其余可用宽度
- **AND** 面板开合不得改变画布 definition 或触发自动保存

#### Scenario: 节点库内容

- **WHEN** 用户查看桌面节点库
- **THEN** 节点按 input、model、control、output 分类展示
- **AND** 每项展示模态图标与完整节点名称
- **AND** 点击节点仍按现有规则添加到画布
- **AND** 节点数量超出视口时节点库独立纵向滚动

### Requirement: 按需详情栏

系统 SHALL 使用单一右侧详情栏承载画布配置、节点配置、结果和运行记录，并提供明确的展开与关闭控制。

#### Scenario: 选择节点

- **WHEN** 用户点击画布节点
- **THEN** 右侧详情栏展开
- **AND** 激活“配置”标签
- **AND** 展示所选节点的现有配置内容

#### Scenario: 打开运行记录

- **WHEN** Pipeline 用户点击顶部“运行记录”入口
- **THEN** 右侧详情栏展开
- **AND** 激活“运行”标签
- **AND** 保留当前 Run 选择、轮询、取消和重试行为

#### Scenario: 执行后查看运行

- **WHEN** 完整执行或“从此节点继续”成功创建 Run
- **THEN** 右侧详情栏展开
- **AND** 激活“运行”标签
- **AND** 选择新创建的 Run

#### Scenario: 查看结果

- **WHEN** 用户在详情栏选择“结果”标签
- **THEN** 面板展示当前所选节点在当前 Run 中的结果
- **AND** 不混用其他节点或其他 Run 的结果

#### Scenario: 关闭详情栏

- **WHEN** 用户点击详情栏关闭按钮
- **THEN** 详情栏收起
- **AND** 当前节点选择、详情标签和 Run 选择保持不变
- **AND** 中央画布恢复占用释放的宽度

#### Scenario: 再次点击顶部详情入口

- **WHEN** 详情栏已打开且当前标签为“配置”
- **AND** 用户再次点击顶部“详情”
- **THEN** 详情栏收起
- **WHEN** 详情栏已打开且当前标签为“结果”或“运行”
- **AND** 用户点击顶部“详情”
- **THEN** 详情栏保持打开并切换到“配置”

#### Scenario: 画布空白处取消选择

- **WHEN** 用户点击画布空白处
- **THEN** 取消节点选择
- **AND** 已展开的详情栏保持打开并保留当前标签
- **AND** 当前标签为“配置”时继续展示画布级名称、描述和未选择节点提示
- **AND** 当前标签为“结果”时继续展示当前 Run 的全部可用结果
- **AND** 当前标签为“运行”时继续展示当前 Run
- **AND** 不因取消选择自动造成布局跳动

### Requirement: 顶部命令分层

系统 SHALL 将文档级和执行级命令保留在顶部栏，并以图标、可访问名称和工具提示表达紧凑命令。

#### Scenario: Pipeline 顶部命令

- **WHEN** 用户编辑 Pipeline
- **THEN** 顶部可访问返回、自动保存状态、撤销、重做、详情、运行记录、另存为模板和执行
- **AND** 执行保持最明显的主命令
- **AND** 运行中、保存中和不可执行状态继续使用现有禁用规则

#### Scenario: 模板顶部命令

- **WHEN** 用户编辑模板
- **THEN** 顶部不展示运行记录、另存为模板或执行入口
- **AND** 仍可访问返回、自动保存状态、撤销、重做和详情
- **AND** 详情栏仍保留“配置 / 结果 / 运行”三个标签
- **AND** “结果”展示未执行空状态，“运行”展示“模板不可执行”占位

#### Scenario: 长标题或异常状态

- **WHEN** 画布名称或自动保存错误文案超出可用宽度
- **THEN** 标题和状态在各自约束内截断
- **AND** 完整状态可通过 `title` 或等价可访问说明读取
- **AND** 命令按钮不得被文本挤出视口

### Requirement: 画布底部工具坞

系统 SHALL 将 React Flow 视图控制固定在画布底部中央，不改变其语义和画布坐标行为。

#### Scenario: 使用视图控制

- **WHEN** 用户查看任意桌面或窄屏画布
- **THEN** 缩小、放大、适配视图和交互锁定控件位于底部中央
- **AND** 每个图标按钮具有可访问名称和悬停提示
- **AND** 工具坞尺寸稳定，不因状态或标签变化导致画布布局位移

#### Scenario: 画布内容位于底部

- **WHEN** 节点接近工具坞区域
- **THEN** 工具坞以浮层方式覆盖画布而不修改节点坐标
- **AND** 用户仍可平移画布将节点移出遮挡区域

### Requirement: 响应式面板行为

系统 SHALL 在小于 `1024px` 的窗口中使用覆盖式、互斥的节点库和详情栏，避免同时压缩中央画布。

#### Scenario: 打开窄屏节点库

- **WHEN** 用户在窄屏点击节点库入口
- **THEN** `240px` 节点面板从左侧覆盖画布
- **AND** 已打开的详情面板关闭
- **AND** 添加节点后节点面板自动关闭

#### Scenario: 打开窄屏详情栏

- **WHEN** 用户在窄屏选择节点或点击详情、运行记录入口
- **THEN** 最大宽度 `320px` 的详情面板从右侧覆盖画布
- **AND** 已打开的节点面板关闭
- **AND** 面板宽度不得超过当前视口

#### Scenario: 390px 窄屏命令可达

- **WHEN** 编辑器宽度为 `390px`
- **THEN** 顶部允许分为两行
- **AND** 返回、状态、撤销、重做、面板入口和 Pipeline 执行均可访问
- **AND** 文本不与按钮重叠或溢出视口

#### Scenario: 中等宽度命令布局

- **WHEN** 编辑器宽度为 `640px` 至 `1279px`
- **THEN** 顶部使用单行布局
- **AND** 详情、运行记录、另存模板和执行只显示图标，通过 `aria-label` 与 `title` 提供完整名称
- **AND** 标题、自动保存状态和命令按钮不得重叠

#### Scenario: 宽屏命令标签

- **WHEN** 编辑器宽度不小于 `1280px`
- **THEN** “另存为模板”和“执行”可显示图标与文字
- **AND** 详情和运行记录保持紧凑图标按钮

#### Scenario: 从窄屏切换到桌面

- **WHEN** 窗口从小于 `1024px` 扩大到不小于 `1024px`
- **AND** 当前打开的是节点库浮层
- **THEN** 清除 `"nodes"` 临时面板状态
- **AND** 桌面常驻 `184px` 节点库正常显示
- **WHEN** 当前打开的是详情浮层
- **THEN** 保留详情栏及其当前标签，并转换为右侧停靠面板

#### Scenario: 从桌面切换到窄屏

- **WHEN** 窗口从不小于 `1024px` 缩小到小于 `1024px`
- **AND** 详情栏当前展开
- **THEN** 保留详情栏及其当前标签，并转换为右侧覆盖面板
- **WHEN** 详情栏当前收起
- **THEN** 窄屏默认不打开任何覆盖面板

### Requirement: 既有编辑与保存契约不回归

系统 SHALL 将本变更限制在编辑器布局与面板状态，不改变业务数据流。

#### Scenario: 自动保存

- **WHEN** 用户编辑名称、描述、节点、连线、位置、尺寸、配置或视口
- **THEN** 继续执行 `800ms` 防抖自动保存
- **AND** 面板开合和详情标签切换不触发保存

#### Scenario: 关键命令

- **WHEN** 用户返回、执行、从节点继续、另存模板或进入图层编辑器
- **THEN** 继续先调用现有 `flush()`
- **AND** 保存失败、校验失败或 `409` 冲突时阻止后续操作

#### Scenario: 节点与运行能力

- **WHEN** 用户添加、删除、拖拽、缩放、连接或执行节点
- **THEN** 节点注册、端口校验、运行投影、取消、重试和下载行为与变更前一致

## MODIFIED Requirements

### Requirement: 画布交互布局

系统 SHALL 在独立画布页提供紧凑顶部命令栏、桌面窄节点库、中央 React Flow 画布、按需右侧详情栏和底部视图工具坞。右侧详情不再在桌面端无条件常驻。

### Requirement: 检查器导航

系统 SHALL 使用“配置 / 结果 / 运行”三个标签承载既有检查器内容。节点选择进入配置，运行记录入口进入运行；关闭面板只影响可见性，不清除当前上下文。

### Requirement: 窄屏画布

系统 SHALL 保持窄屏 `minZoom=0.25` 和无平移边界，并以互斥覆盖面板替代常驻左右栏。窄屏面板不得改变保存、执行或节点选择的数据语义。

## REMOVED Requirements

### Requirement: 桌面端常驻右侧检查器

**Reason**: 无条件占用 `288px` 会显著压缩画布，而多数画布导航操作不需要持续查看详情。

**Migration**: 原检查器内容和标签完整迁移到可展开的 `320px` 详情栏；选择节点或打开运行记录时自动展开，也可通过顶部入口手动控制。
