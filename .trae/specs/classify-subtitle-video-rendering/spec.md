# 视频字幕翻译按视频类型压制规格

## 为什么

产品视频要求所有字幕都不带灰色底板，开箱视频需要保留现有底板策略。当前流程没有视频类型字段，普通文字、产品名称 PNG 和预览均按同一套规则处理，无法按任务选择策略。

## 变更内容

- 在视频字幕翻译流程入口提供“新建产品视频任务”和“新建开箱视频任务”，创建时明确选择类型，不根据文件名、产品名称或模型结果猜测。
- 工作区新增 `video_category`：`product` 为产品视频，`unboxing` 为开箱视频。整个任务统一使用一个类型，两份输入视频共享该任务类型。
- 产品视频：所有字幕底板统一透明，包括标题、正文、脚注、普通字幕、产品名称混合字体 PNG，以及失败回退路径。
- 开箱视频：保持当前自动配色、底板和逐条人工覆盖规则。
- 工作区顶部显示类型，允许有写权限的用户在无阶段任务执行时切换；切换仅使排版和当前成片引用失效，保留提取结果、译文及逐条样式。
- 历史工作区、历史任务快照及旧调用方缺少类型时按 `unboxing` 处理，不批量重写历史数据或成片。
- 产品视频的底板控件不提供覆盖入口；保留已有底板配置，切回开箱视频后恢复生效。

### 策略对照

| 项目 | 产品视频 | 开箱视频 |
| --- | --- | --- |
| 有效字幕底板 | 所有字幕 `#00000000`，不绘制可见底板 | 当前自动规则或逐条人工覆盖 |
| 自动文字色 | 保持当前背景判断：近白黑字，其余白字 | 保持当前规则 |
| 人工文字色、字体和字号 | 保留 | 保留 |
| 产品名称字体 | 型号 Avenir Black、规格 Avenir Light | 型号 Avenir Black、规格 Avenir Light |
| 背景未知或复杂 | 保留文字，不自动添加底板或描边 | 白字加 `#33333359` 深灰底板，约 35% 不透明度 |
| 预览和压制 | 同一透明底板策略 | 同一现有策略 |

本规格将“产品视频所有字幕不带灰色底板”落实为**产品视频统一无可见字幕底板**，人工配置的其他颜色底板也不生效，避免绕过任务策略。视频本身已有的背景、参考视频中已有文字底板、播放器黑色留边及画布背景不属于本次移除范围。

已检查现有相关计划、任务及验收清单；没有覆盖产品/开箱视频分类的已有变更。本次使用独立 change-id `classify-subtitle-video-rendering`，不重启其他规格遗留的真实供应商验收任务。

## 新增需求

### 需求：在流程入口明确视频类型

系统应当在创建字幕翻译任务前提供两种明确入口，并将所选类型写入创建请求。入口文案直接说明“产品视频 · 字幕无底板”和“开箱视频 · 保持现有底板规则”，不增加识别模型调用或独立分类步骤。

#### 场景：新建任务

- **当**用户选择“新建产品视频任务”或“新建开箱视频任务”
- **则**分别创建 `video_category=product` 或 `video_category=unboxing` 的工作区，后续仍使用既有导入、提取、翻译、校对和压制流程。

#### 场景：查看与修改类型

- **当**用户重新打开工作区或查看历史列表
- **则**可看到已保存类型；无字段的旧工作区显示开箱视频。
- **当**Viewer 查看，或工作区正在提取、翻译、压制
- **则**类型只读，入口及修改控件遵守已有权限和 busy 状态，不产生修改请求。

### 需求：持久化与接口兼容

工作区创建、读取、列表、更新、历史记录及阶段任务快照应当包含视频类型。合法值只有 `product` 和 `unboxing`；旧创建请求与旧数据缺失字段时默认 `unboxing`，更新请求省略字段时保留原类型，显式 `null` 或非法值返回现有风格的安全校验错误。

#### 场景：历史数据及独立 SDK

- **当**读取缺少类型的旧 payload、旧任务快照，或独立包调用方提供的 render video 字典没有类型
- **则**沿用开箱视频当前行为；GET 不补写数据库，不发起名称识别模型调用。
- **当**平台调用预览或压制编译器
- **则**在运行时 video 字典传入工作区或冻结任务快照中的类型，不能将“产品视频”混同于字幕中的“产品名称”。

### 需求：产品视频的底板策略不可被分段设置覆盖

服务端应当在统一配色/排版路径决定产品视频的有效底板为 `#00000000`，优先级高于自动规则和 `style.background_color`。普通 MediaKit text 元素、混合字体 PNG、PNG 存储/物化失败后的普通文字压制，都必须执行同一策略。

有效文字色应基于当前画面背景判断和人工 `style.text_color`，不能因已忽略的人工底板配置被强制改成白色。不得将 VLM 输出的 `segment.background_color` 改成透明，也不得新增描边、阴影或其他视觉替代物。

#### 场景：全字幕覆盖及失败回退

- **当**产品视频包含标题、正文、脚注、多产品名称、无产品名称文字、复杂/未知背景或非透明人工底板
- **则**所有有效字幕都不绘制可见底板；文字、字体、字号、位置、时间及非底板覆盖值保留。
- **当**产品图层无法生成、存储或物化
- **则**既有可读文字回退仍使用透明底板，不重新添加灰色底板，不因无底板新增硬拦截。

## 修改需求

### 需求：开箱视频完整保留当前底板规则

开箱视频自动模式应当继续按当前阈值处理：RGB 通道均至少 245 时黑字无底板；均至多 16 时白字无底板；其他或未知背景白字加 `#33333359`。人工底板及文字色覆盖的优先级、已有对比提示、单行扩框、角色字体和产品名称自动判定保持。

#### 场景：开箱回归

- **当**相同字幕和视频从旧调用路径或 `unboxing` 路径编译
- **则**底板、文字色、字体、布局、时间和音轨策略与当前版本一致，包括透明人工底板和非透明自定义底板。

### 需求：预览、控件及提示与有效策略一致

校对编辑器、DOM 文字示意、服务端排版预览、产品 PNG 和 PNG 加载失败占位应当统一按任务类型显示。产品视频只显示“产品视频：字幕无底板”，不显示可编辑的底板模式、颜色、不透明度和原始底板字段；文字色、字体等其他编辑能力保留。

产品类型下背景未知、扩宽区域或低对比的提示不得错误宣称已添加灰色底板，也不得建议通过启用底板解决。原有开箱提示保持。两类任务均不得重新引入产品型号/规格人工校验提示。

#### 场景：切换与缓存

- **当**工作区从开箱切到产品
- **则**旧灰底 PNG、排版摘要和 DOM 底板不再用于当前预览；重新计算后全部透明。
- **当**切回开箱
- **则**原逐条底板配置恢复生效；产品阶段未删除或覆盖这些配置。

### 需求：切换类型的失效、并发和幂等

类型变化应当纳入渲染内容变更，清空当前 `output_asset_id`、render 阶段引用及派生布局，增加 revision；保留输入视频、原文、译文、自动型号/规格结果及其识别指纹、逐条样式，不重跑提取或翻译。

渲染任务冻结类型，并将有效类型和新排版版本纳入幂等依据；图层缓存键覆盖有效类型、底板策略及排版版本。相同内容/类型/版本的重复渲染仍幂等。

UI 在运行期间禁用类型修改。通过 API 更新类型时继续遵守 revision 校验；若已有压制任务，其晚到结果不得写回类型已变更的当前工作区。已提交供应商任务恢复轮询使用原任务快照，不重新按最新类型解释旧任务或删除旧图层。

#### 场景：历史输出与并发修改

- **当**类型切换后原压制任务完成
- **则**结果保留在原任务历史，不成为当前工作区的新成片。
- **当**用户持旧 revision 更新类型
- **则**返回 409，不覆盖远端修改。
- **当**历史任务没有类型或新旧排版版本不同
- **则**恢复旧任务仍按原快照；用户新发起压制采用新版策略，不误复用旧版任务。

## 移除需求

### 需求：所有任务无条件采用同一底板规则

**原因**：产品视频需要全任务统一无底板，开箱视频继续保留当前策略。

**迁移**：旧数据默认开箱，无全库迁移；产品视频忽略但保留逐条底板覆盖。升级不修改历史成片，重新压制才产生新版输出。

## 发布和验收边界

- 独立包由当前 `0.3.1` 发布为 `0.3.2`；排版版本更新为 `single-line-adaptive-panel35-video-category-v4`，字典版本保持。
- 平台固定引用 `vendor/video_subtitle_grounding-0.3.2-py3-none-any.whl`，源码归档为 `exports/video-subtitle-grounding-0.3.2-source.tar.gz`，保留旧版供同步回滚。
- 线上仍只拉平台仓库，通过原部署脚本安装 wheel、构建前端和重启；需一起发布后端契约、前端及 wheel。回滚也需同步恢复三者。
- 本阶段只编写规格、任务和验收清单，评审后实施；不修改代码、生产数据，不提交、推送或部署。
- 离线验收覆盖两类背景矩阵、实际字体 PNG 的透明像素、失败回退、memory/SQL 工作区、类型失效、权限、并发及任务幂等。

- 不发起真实计费模型或 MediaKit 调用。离线验证不能证明真实供应商成片已验收；执行状态与限制必须单独记录。
