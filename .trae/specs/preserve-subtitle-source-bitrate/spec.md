# 字幕压制沿用源视频码率

状态：用户已确认，实现与离线验收完成；真实编码产物待另行授权。基于用户要求及 2026-11-17 官方文档核对。

## 目标与接口依据

产品视频和开箱视频压制字幕时，读取实际底片（工作区 `clean_video_asset_id`，即无字幕视频）的视频流码率，作为 MediaKit 输出编码的目标码率。参考视频用于字幕提取，不能代替底片提供码率。

官方文档：https://docs.volcengine.com/docs/intelligent-processing/multi-track-edit?lang=zh

文档 `output.codec` 表明确：

- `video_bit_rate` 是可选 Integer，单位 bps。
- 不设置时由 `crf` 控制，设置后 `crf` 不生效。
- 音频参数 `audio_bitrate` 单位为 kbps，不能与视频码率混用。

请求示例：源视频流 `bit_rate="7000"`，则传：

```json
{"output": {"format": "mp4", "codec": {"video_bit_rate": 7000}}}
```

若原始值是 7000 kbps，则参数为 7000000；FFprobe `streams[].bit_rate` 本身是 bps，直接解析整数，不乘除 1000。

该参数设置的是重新编码的目标码率；字幕叠加需要重新编码，不承诺产物逐比特相同或测得平均码率严格等于目标值。

## 当前链路

`SubtitleVideoPathInspector.inspect` 已用 FFprobe 读取 `-show_streams -show_format`，但 `SubtitleVideoMetadata` 仅保存尺寸、时长、方向、帧率和音轨标记。工作区及 render 快照没有码率。

独立包 `layout.compile_subtitle_project` 当前只生成 `output.format/fps/disable_audio`。平台和独立渲染服务均使用该共享编译器；文字、产品 PNG 及 PNG 物化失败回退也共用该入口。

旧资产即使已有尺寸/帧率，也可能未保存码率；`ensure_metadata` 当前不会因仅缺码率而重新探测。新设计需要覆盖旧工作区重新压制。

## 方案比较与选择

1. **推荐：读取视频流码率，保存在元数据和新任务快照，由共享编译器写入编码参数。** 新导入复用现有 FFprobe；旧资产在首次新压制时按需探测；统一覆盖文字和 PNG。
2. 每次压制重新下载探测底片。实现直接，但已有有效码率时仍增加下载和探测开销。
3. 使用容器总码率或固定 7000。容器码率通常包含音频与封装，固定值不能代表不同源视频，不采用。

## 元数据与缺失处理

- 新增可选 `video_bit_rate: positive integer | null`，统一为 bps。作用于共享视频展示元数据、平台 `SubtitleVideoMetadata` 和必要的前端数据类型。
- 读取与尺寸探测相同的视频流 `bit_rate`。仅接收有限、正整数；拒绝布尔值、0、负数、N/A、浮点值或损坏字符串，不阻断原有视频导入。
- 不使用 `format.bit_rate` 冒充纯视频流码率，不添加任意倍数、不限制到经验推荐码率范围。
- 无法获得视频流码率时，省略 `output.codec.video_bit_rate`，沿用供应商默认编码并返回安全警告 `source_video_bit_rate_unavailable`；不新增硬失败。
- 记录码率是否已探测，区分“旧资产未探测”和“已探测但不可用”，避免重复下载同一旧资产。
- 新导入/上传与成片存储复用现有 FFprobe，不新增模型或 MediaKit 调用。

## 新压制、历史工作区与任务快照

- 新 render 任务包含独立编码策略版本 `source-video-bit-rate-v1`，纳入幂等身份；字幕排版版本、品牌规则版本、字典版本保持不变。
- 新任务优先使用已保存的底片流码率。旧工作区缺码率时，在执行新策略任务、尚未提交供应商前，安全下载底片并探测一次。
- 探测结果以当前任务冻结的 `clean_video_asset_id` 为来源，写入任务的编码解析结果，再用于提交；探测过程中工作区编辑不改变该任务来源。现有 revision、类型和晚到结果保护继续有效。
- 安全记录已解析码率和探测完成状态（包括不可用），重启后复用结果。资产元数据可缓存探测结果；不批量迁移或改写历史工作区。
- 已冻结的旧任务不补入新编码策略；已提交供应商任务只轮询恢复，不重编译或改变旧编码参数。
- 旧任务重新提交到供应商且需要重新编译时，作为新策略执行，冻结新策略身份；已提交任务的恢复保持原策略。
- 历史成片保持原样；用户新发起压制才使用新策略。

## 共享输出编译与范围

共享编译器在有效码率存在时生成 `output.codec.video_bit_rate`。没有码率时保持原输出字段，附带缺失警告；不向顶层 `output` 或轨道元素直接写入该参数。

独立渲染 API 接受调用方提供的 bps 元数据并统一映射；从独立视频探测获得的元数据也包含码率。不因本次修改扩大远程 URL 的下载授权范围。

普通文字、PNG、物化失败回退共用同一份冻结视频元数据，保持相同码率。分辨率、帧率、音轨策略、字体、底板、时间、品牌排除保持现有行为。前端只映射缺失提示，不增加码率编辑控件或冗余说明布局。

日志只新增安全的码率数值、来源类型、探测状态和编码策略版本；不得输出签名媒体 URL、凭据或原始模型响应。

## 验收

- FFprobe 视频流 7000 → `output.codec.video_bit_rate=7000`；7000000 → 7000000，无单位误转换。
- 视频流与容器/音频码率不同，使用视频流；缺失和损坏值省略参数并安全提示。
- 两种视频类型、普通文字、PNG、物化失败回退和独立编译/渲染入口的输出一致。
- 已有有效码率不重新下载；旧资产首次新压制按需探测，已探测不可用不无限重复。
- 新任务冻结底片来源、编码策略和解析结果；旧已提交任务的恢复/重试不重新提交或改编码。
- 字幕排版、品牌排除、音轨、revision、晚到写回和历史成片回归通过。
- 共享包和平台 pytest、Ruff、编译、diff、前端类型/提示测试、产物一致性和隔离安装通过。
- 若涉及可见提示，使用已有 Vitest 与三视口 Playwright 验证。
- 真实编码产物的目标码率、清晰度和体积需另行授权后验收。
