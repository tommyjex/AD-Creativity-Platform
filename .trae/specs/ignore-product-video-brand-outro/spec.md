# 视频品牌 Logo 与固定标语排除设计

状态：用户已批准，已于 2026-11-17 完成实现与离线验收；发布包 0.3.3 已生成，尚未提交、推送或部署。真实模型与成片质量待另行授权验收。

## 目标与范围

产品视频与开箱视频遇到独立品牌 Logo 或固定品牌标语时，均不作为字幕提取，不进行翻译，也不生成覆盖品牌画面的译文图层。规则不依赖视频类型或是否位于片尾。

用户提供的两张参考图分别为白底蓝色 Tineco Logo，以及白底蓝色标语 `Live Easy. Enjoy Life.`。它们用于说明排除对象，不作为运行时图片识别模板，也不要求每次调用上传参考图。

- 规则统一作用于产品视频、开箱视频，以及缺少类型的旧调用方；共同使用该提取链路的独立字幕提取工具也应用同一品牌排除规则。
- 现有一般 Logo、水印、包装印刷文字排除提示继续保留；固定品牌标语排除是新增的统一规则。
- 不移除、遮盖或修改原视频中的 Logo 和标语。
- 产品名称、型号、规格及普通功能说明继续提取和翻译；包含品牌名的产品说明不因此被整体排除。
- 不自动修改历史工作区或历史成片。旧工作区重新提取后应用新规则。

## 当前实现与问题

独立包 `provider.py` 的现有提示词已排除一般品牌 Logo，但没有明确识别固定品牌标语。两类视频共用提取器，因此本次直接增强共享规则，不需要为提取传入或判断视频类型。

翻译任务默认处理所有未排除、未翻译的记录。因此，只要标语被提取为普通文字，它就会进入翻译和后续压制。

## 方案选择

| 方案 | 收益 | 限制 |
| --- | --- | --- |
| 统一提示词与严格结果过滤，推荐 | 两类视频均按画面语义排除品牌内容，固定文字漏网时仍可移除；无需增加模型调用 | OCR 严重误识别时不能靠精确文本匹配保证识别质量，需真实视频验收 |
| 只增强提示词 | 改动最少 | 无法保证模型偶尔仍输出标语时不进入翻译 |
| 模糊关键词过滤 | 可匹配更多识别变体 | 容易误删含品牌名或相似词的产品说明，不采用 |

## 推荐设计

### 统一提取规则

独立服务和 provider 始终应用同一品牌排除规则，不新增视频类型参数，不按产品/开箱分支选择提示词，也不引入可变的请求级 provider 状态。现有调用签名和严格输出 schema 保持兼容。

共享提示词明确说明：

- 独立品牌 Logo 与固定标语不属于目标字幕，包括但不限于视频末尾的 Tineco 品牌收尾画面；出现位置不影响排除规则。
- 图形化 Tineco Logo 即使被识别为文字也不输出。
- 固定标语 `Live Easy. Enjoy Life.` 不输出，动画渐显、单独出现或分成视觉行显示均属于同一句品牌标语。
- 继续扫描其他时段及同一画面中符合既有定义的产品说明、标题、功能卖点和脚注，不因出现品牌片尾而提前结束扫描。

保留现有 Files API 上传、采样、轮询、清理、严格 JSON Schema、bbox 和视觉角色约定，不增加 VLM 调用。

### 严格结果过滤

独立包新增可复用的品牌文字规则，在有效字幕写入平台工作区之前过滤确定的品牌条目。

- 独立完整文字为 `Tineco` 的条目按本次已明确排除的品牌标识处理；大小写和首尾空白不影响匹配。
- 独立完整标语为 `Live Easy. Enjoy Life.` 的条目被过滤。允许大小写、Unicode 兼容形式、空白及句点有无的差异，但不使用包含匹配、编辑距离或任意 OCR 拼写纠错。
- 分行情况仅在相同非 legacy 的 `block_id`、连续 `line_index`、相互重叠的显示区间中，完整重组为这句标语时过滤对应的行；不得单凭 `Live Easy` 或 `Enjoy Life` 两个短语分别过滤。
- `Tineco FLOOR ONE S7`、`Powered by Tineco`、含额外产品说明的整行，以及无法可靠完整重组的短语保留。
- 不按“最后若干秒”或固定画面坐标粗切字幕，避免丢失与片尾临近的正常说明。
- 在产品和开箱工作区中，确定的独立固定品牌文字均作为品牌内容排除；在片尾以外或重复出现时同样不提取、不翻译。

过滤只影响返回的有效字幕集合，不修改原始模型输出；若记录模型原文，继续遵守仅写受控 TLS 日志的约束。日志只新增安全的类型、规则版本、过滤数量及分类计数，不输出被过滤的原文。

### 翻译兜底与空结果

提取后的品牌条目不会写入新工作区，也不会进入翻译批次、上下文或产品名称识别。翻译入口复用同一严格规则保护漏网记录，过滤后的条目不得被当作翻译失败或要求人工补齐。

历史工作区不做后台自动清理；重新提取是更新旧提取结果的方式。若在旧工作区直接发起新翻译，确定的品牌条目也不提交给模型；返回安全的“品牌片尾已跳过”提示，保留已有源记录及人工样式，不删除历史译文或成片。后续新预览/压制不为确定的品牌条目生成译文覆盖层。

只含 Logo/标语的视频可正常返回空字幕列表。无有效待翻译内容时沿用安全的无待处理提示，不产生模型调用。没有可压制字幕时不新增空字幕硬失败链路或付费任务，沿用无可压制字幕提示；原视频中的品牌内容保持。

### 类型切换、快照与兼容

现有类型切换保留已提取原文、译文、样式及产品名称判定，不自动重新提取。

- 类型切换不启用或关闭品牌排除；两类视频采用相同有效品牌条目集合，不因切换类型恢复 Logo 或标语。
- 产品/开箱的底板策略和现有类型切换失效规则保持；本次不因品牌排除新增按类型区分的 extract/translate 写回限制。
- 新提取、翻译及压制任务的幂等依据加入品牌规则版本。render 保留既有类型和排版版本身份；extract/translate 无需为相同品牌规则额外区分视频类型。
- 已提交旧任务继续按冻结快照和既有恢复规则处理，不将新规则冒充为旧任务的执行策略；已提交旧压制任务不重新编译，也不删旧图层。原有 revision、失效和晚到结果保护继续有效。

### 发布

独立包从 `0.3.2` 更新为 `0.3.3`，平台固定引用新 wheel，同时提供 sdist、源码归档与 SHA。底板、字体和几何排版算法不变，沿用当前排版版本；新增独立品牌规则版本进入任务策略身份。

保留已有包与未提交改动。线上仍只拉平台仓库，通过既有部署脚本安装随仓库分发的 wheel。本次设计不授权提交、推送、生产部署或真实计费模型调用。

## 实施范围

- 独立包：新增品牌规则模块；修改 `provider.py`、`service.py` 的统一提示词与结果过滤；更新包版本和对应离线测试，不增加类型上下文传递。
- 平台：修改 `backend/app/services/subtitle_translation.py` 的翻译选择/结果处理、预览/压制排除及规则版本身份；复用既有快照和晚到结果保护，尽量保持薄适配层职责。
- 前端：仅在已有提示与阶段可用性需要同步时调整，保留创建按钮与工作区现有布局，不重新增加已删除的灰色说明文字。
- 发布：requirements、vendor、源码归档、发布说明和隔离安装验证。

## 验收要求

- 产品视频和开箱视频中的独立 Logo、完整 slogan、大小写/句点/空白变体及合规多行 slogan 均不出现在新提取结果和翻译请求中；片尾以外及重复出现时也排除。
- 普通产品名称、含 Tineco 的说明、相似但不完整短语、不同块/不同时间的短语以及正常片尾字幕保留。
- 两类视频、旧默认调用及独立工具使用同一品牌排除规则；普通字幕提取回归保持，调用签名与输出 schema 不变。
- 只有品牌内容时返回空字幕，不发起无意义翻译、名称识别或压制任务。
- 历史数据不自动重写；新阶段采用新规则；切换类型不恢复品牌内容，不改变既有 extract/translate/render 的 revision 和晚到结果保护，已提交旧任务仍能恢复。
- 普通文字/PNG/失败回退预览和压制均不增加品牌译文图层；正常字幕的透明底板、字体、位置、时间和音轨回归保持。
- 包源码、wheel/sdist、平台固定引用和隔离导入一致；通过相关离线测试、Ruff、编译、diff 检查。涉及前端行为时补充既有 Vitest 与三视口 Playwright。
- 离线 mock 不代表真实模型已正确忽略品牌画面；真实提取与成片质量需另行授权后验收。
