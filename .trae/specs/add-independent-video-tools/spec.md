# 独立视频工具模块 Spec

## Why

当前系统的视频生成能力只能在项目分镜工作流内使用，无法处理不属于项目的视频素材。需要增加与项目、资产库并列的独立工具模块，支持人物打码与全模态参考生视频，并将全部输入、输出保留在可追溯的工具资产库中。

## What Changes

- 顶部导航新增“工具”入口，并提供独立页面 `/workspace/tools`。
- 新增独立 `ToolTask` 领域模型，承载无项目归属的工具任务、状态、输入快照、供应商任务 ID、脱敏错误信息和完成时间。
- 资产支持与工具任务关联；工具资产不要求项目 ID，现有项目资产保持原有项目归属与行为。
- 工具页采用两个标签页：`视频人物打码`、`全模态参考生视频`；每个标签页独立配置、提交和查看当前任务结果。
- “视频人物打码”标签页调整为左侧纵向任务配置区，`当前任务`卡片显示在`人物打码配置`下方，右侧显示打码前/后视频播放窗口，并支持播放器放大预览。
- “视频人物打码”标签页进一步优化为上方横向配置卡片、下方两栏式任务与视频对比工作区；历史任务需支持选中后驱动右侧打码前/后播放器。
- 接入 AI MediaKit `POST /api/v1/tools/face-blur-video` 与任务查询接口，异步完成人物打码。
- 接入现有 ModelArk Seedance 视频生成适配层，允许选择受限的四个模型并使用参考图、参考视频、参考音频生成视频。
- 资产库支持展示、筛选和预览工具资产，并标注其所属工具任务和输入/输出角色；修复来源筛选为“工具资产”时再次点击筛选报错的问题。

## Impact

- Affected specs: 工作区顶级导航、资产库、资产持久化、异步任务、视频生成、外部服务错误处理。
- Affected code: `frontend/components/layout/app-shell.tsx`、`frontend/app/workspace/`、`frontend/components/workspace/workspace-asset-library.tsx`、`frontend/lib/api-client.ts`、`backend/app/db/models.py`、数据库迁移、`backend/app/schemas/`、`backend/app/repositories/`、`backend/app/api/routes.py`、`backend/app/services/mediakit.py`、`backend/app/services/modelark.py`、资产存储服务及相关测试。

## ADDED Requirements

### Requirement: 工具模块导航与页面

系统 SHALL 在顶级导航中提供与“项目”“资产库”平行的“工具”入口，并在 `/workspace/tools` 提供独立工具工作台。

#### Scenario: 进入工具工作台

- **WHEN** 用户点击顶部“工具”
- **THEN** 系统打开 `/workspace/tools`
- **AND** 页面展示“视频人物打码”和“全模态参考生视频”两个标签页
- **AND** 当前标签页具有独立的配置区和当前任务结果区

### Requirement: 工具任务与工具资产归属

系统 SHALL 使用独立的 `ToolTask` 记录无项目归属的工具执行；工具上传素材、处理产物和生成产物 SHALL 关联到对应工具任务，不创建或要求选择项目。

#### Scenario: 创建工具任务

- **WHEN** 用户在任一工具标签页提交有效配置
- **THEN** 系统创建包含工具类型、状态、输入快照和创建时间的 `ToolTask`
- **AND** 任务初始状态为 `queued`，开始供应商调用后更新为 `running`
- **AND** 该任务不出现在项目列表中

#### Scenario: 保存工具资产

- **WHEN** 用户在工具页上传参考素材，或工具任务成功生成/处理视频
- **THEN** 系统将文件持久化到对象存储并创建资产记录
- **AND** 资产关联 `tool_task_id`
- **AND** 资产不要求 `project_id`
- **AND** 资产元数据保存工具类型、输入/输出角色、供应商与可安全公开的任务追踪信息

#### Scenario: 保持项目资产兼容

- **WHEN** 系统读取、创建、删除或展示现有项目资产
- **THEN** 项目资产仍必须具备 `project_id`
- **AND** 既有项目详情、画布、分镜和资产库工作流不因工具资产而改变语义

### Requirement: 视频人物打码

系统 SHALL 提供基于 AI MediaKit 视频人脸打码 API 的异步视频处理能力。

#### Scenario: 提交人物打码

- **WHEN** 用户选择或上传一个工具视频资产，选择打码方式（`mosaic` 或 `blur`）和打码强度（`low`、`medium` 或 `high`），并提交任务
- **THEN** 系统创建 `ToolTask(type=face_blur_video)`
- **AND** 使用该视频的受控可访问 URL 调用 `POST https://mediakit.cn-beijing.volces.com/api/v1/tools/face-blur-video`
- **AND** 请求只传递用户选择的 `mask_mode`、`mask_strength` 及 `video_url`
- **AND** `face_confidence` 与 `face_box_expand` 使用 MediaKit API 默认值
- **AND** 系统保存供应商 `task_id`、安全格式的 `request_id` 与提交状态

#### Scenario: 人物打码完成

- **WHEN** MediaKit 任务查询结果为完成且返回结果视频 URL
- **THEN** 系统下载/转存结果视频至本系统对象存储
- **AND** 创建关联该工具任务的输出视频资产
- **AND** 资产元数据包含 `provider=mediakit`、`operation=face_blur_video`、打码方式、强度和输出时长
- **AND** 工具任务状态更新为 `succeeded`
- **AND** 工具页可预览和下载结果视频

#### Scenario: 人物打码页面查看处理前后视频

- **WHEN** 用户打开“视频人物打码”标签页并选择或上传输入视频
- **THEN** `人物打码配置`与`当前任务`卡片在左侧纵向排列
- **AND** `当前任务`卡片显示在`人物打码配置`下方
- **AND** 页面右侧显示打码前视频播放器
- **AND** 当当前任务存在成功输出资产时，页面右侧同时显示打码后视频播放器
- **AND** 两个播放器均保持视频原始宽高比，不裁切画面

#### Scenario: 放大查看人物打码播放器

- **WHEN** 用户对打码前或打码后播放器执行放大操作
- **THEN** 系统打开预览弹窗播放对应视频
- **AND** 弹窗内播放器适配视口尺寸，保持原始宽高比
- **AND** 用户可以关闭弹窗回到人物打码配置页面

#### Scenario: 横向配置人物打码参数

- **WHEN** 用户打开“视频人物打码”标签页
- **THEN** `人物打码配置`卡片位于页面顶部
- **AND** 输入视频、打码方式、打码强度三个配置项在桌面宽度下显示在同一行
- **AND** 提交按钮与配置项保持同一卡片内的紧凑操作关系
- **AND** 在窄屏宽度下配置项可按响应式规则换行，但不得溢出或遮挡

#### Scenario: 从任务列表选择人物打码历史任务

- **WHEN** 页面存在一个或多个 `face_blur_video` 任务
- **THEN** 配置卡片下方左栏显示任务列表模块
- **AND** 每个任务项展示任务状态、创建时间或任务 ID、输入视频摘要和关键配置
- **AND** 用户可以选中一个历史任务
- **AND** 只有被选中的历史任务会驱动右侧视频播放模块加载对应打码前与打码后视频
- **AND** 未选中任务时，右侧视频播放模块不得展示旧任务的打码后视频

#### Scenario: 对比播放选中任务的打码前后视频

- **WHEN** 用户选中一个人物打码任务
- **THEN** 右侧视频播放模块展示该任务输入视频作为打码前视频
- **AND** 当该任务存在成功输出资产时，右侧展示该任务输出视频作为打码后视频
- **AND** 当该任务仍在处理中或失败且无输出资产时，打码后区域展示对应空态或状态提示
- **AND** 打码前与打码后播放器均可播放、放大预览，并保持原始宽高比

#### Scenario: 上传新视频后重置播放上下文

- **WHEN** 用户在人物打码配置中上传一个新视频
- **THEN** 系统自动清空当前选中的历史任务
- **AND** 右侧视频播放模块清空之前已加载的打码后视频
- **AND** 打码前视频播放卡片立即预览新上传的视频
- **AND** 用户基于新上传视频提交任务后，任务完成时打码后视频卡片自动刷新为该任务输出视频

#### Scenario: 人物打码失败

- **WHEN** MediaKit 提交、轮询或结果转存失败
- **THEN** 工具任务状态更新为 `failed`
- **AND** 前端展示可理解的失败提示和重试入口
- **AND** 系统只保存并返回安全的错误码、请求 ID、任务 ID 和阶段信息
- **AND** 系统不得暴露 API Key、供应商原始响应体或堆栈信息

### Requirement: 全模态参考生视频

系统 SHALL 提供独立于项目的全模态参考生视频能力，允许用户输入提示词并使用工具资产或本地上传的图片、视频、音频作为参考素材。

#### Scenario: 配置全模态生视频

- **WHEN** 用户在“全模态参考生视频”标签页输入非空提示词
- **THEN** 用户可以选择下列任一模型：
  - `doubao-seedance-2-5-260628`
  - `doubao-seedance-2-0-260128`
  - `doubao-seedance-2-0-fast-260128`
  - `doubao-seedance-2-0-mini-260615`
- **AND** 用户可以选择时长 `4`、`8` 或 `12` 秒
- **AND** 用户可以选择画幅 `16:9`、`9:16` 或 `1:1`
- **AND** 用户可以上传或从工具资产中选择参考图、参考视频和参考音频
- **AND** 第一阶段不提供首帧、尾帧或首尾帧控制

#### Scenario: 提交全模态生成

- **WHEN** 用户提交有效的生视频配置
- **THEN** 系统创建 `ToolTask(type=multimodal_video_generation)` 并保存完整输入快照
- **AND** 上传的参考素材先被保存为关联该任务的工具输入资产
- **AND** 系统向所选 Seedance 模型发送提示词和所有已选择的参考素材 URL
- **AND** 请求固定使用 `720p` 分辨率并开启音频生成
- **AND** 系统不得向请求添加首帧、尾帧或未选择的参考素材

#### Scenario: 全模态生成完成

- **WHEN** Seedance 任务成功返回视频 URL
- **THEN** 系统将视频转存为关联该工具任务的工具输出资产
- **AND** 输出资产元数据包含模型 ID、提示词摘要、时长、画幅、分辨率、音频开关、各模态参考数量及供应商任务 ID
- **AND** 工具任务状态更新为 `succeeded`
- **AND** 工具页显示可播放预览、下载入口、任务参数及所用参考素材

#### Scenario: 全模态生成失败与重试

- **WHEN** Seedance 任务创建、轮询或结果转存失败
- **THEN** 系统将工具任务标记为 `failed` 并显示可理解的失败提示
- **AND** 重试 SHALL 基于保存的输入快照创建新的工具任务和新的输出资产
- **AND** 已上传参考素材保持在资产库中，不因任务失败而删除

### Requirement: 工具素材管理

系统 SHALL 为两个工具提供统一的工具资产选择与本地上传能力。

#### Scenario: 上传工具参考素材

- **WHEN** 用户上传符合类型和大小限制的图片、视频或音频文件
- **THEN** 系统将其保存为工具输入资产并关联当前工具任务
- **AND** 用户可在当前工具配置中移除该素材引用
- **AND** 移除引用不得删除已保存的工具资产

#### Scenario: 复用工具资产

- **WHEN** 用户选择先前保存的兼容工具资产作为参考素材或人物打码输入
- **THEN** 系统只建立当前工具任务对该资产的输入引用
- **AND** 系统不复制原资产文件
- **AND** 资产类型不兼容时必须拒绝选择

### Requirement: 资产库工具资产展示

系统 SHALL 在资产库中展示工具资产，并能够与项目资产区分。

#### Scenario: 查看工具资产

- **WHEN** 用户打开资产库
- **THEN** 用户可以按资产来源筛选“项目资产”与“工具资产”
- **AND** 工具资产卡片显示工具类型、输入/输出角色、任务状态和创建时间
- **AND** 用户可以预览、下载和删除工具资产

#### Scenario: 工具资产来源筛选稳定提交

- **WHEN** 用户在资产库中将来源筛选设置为“工具资产”并点击“筛选”
- **THEN** 系统展示工具资产列表或空状态
- **AND** 页面不得抛出运行时错误、导航错误或接口参数错误
- **AND** 再次点击“筛选”仍保持在工具资产视图并正常渲染
- **AND** 其他筛选项为空时不得向项目资产接口传递无效项目条件

#### Scenario: 删除工具资产

- **WHEN** 用户确认删除一个工具资产
- **THEN** 系统删除对应对象存储文件与资产记录
- **AND** 不影响任何项目资产
- **AND** 不自动删除同一工具任务的其他输入或输出资产

### Requirement: 工具任务状态与错误安全

系统 SHALL 为工具任务提供可轮询的状态查询，并对外部服务错误进行脱敏。

#### Scenario: 轮询任务状态

- **WHEN** 前端存在 `queued` 或 `running` 工具任务
- **THEN** 前端轮询工具任务状态直至其达到 `succeeded` 或 `failed`
- **AND** 用户可以离开工具页面后返回并查看持久化任务状态与产物

#### Scenario: 外部服务错误

- **WHEN** MediaKit 或 ModelArk 返回错误
- **THEN** API 只返回已白名单化的供应商错误码、请求 ID、供应商任务 ID 和执行阶段
- **AND** 日志与响应不得包含密钥、签名 URL 查询参数、原始错误正文或调用栈

## MODIFIED Requirements

### Requirement: 资产模型与资产库查询

系统 SHALL 支持两种资产归属：项目资产必须关联 `project_id`；工具资产必须关联 `tool_task_id` 且可不关联 `project_id`。资产查询、预览 URL、下载与删除接口 SHALL 按实际归属进行权限、存储和生命周期处理。

#### Scenario: 查询混合资产库

- **WHEN** 用户请求资产库列表且未指定来源筛选
- **THEN** 系统返回项目资产与工具资产
- **AND** 每个资产返回明确的归属来源和关联标识
- **AND** 指定项目筛选时仅返回该项目资产
- **AND** 指定工具来源筛选时仅返回工具资产

### Requirement: Seedance 视频生成适配层

现有 Seedance 视频生成适配层 SHALL 支持每个独立工具任务传入受白名单限制的模型 ID、提示词、参考图 URL、参考视频 URL、参考音频 URL、时长和画幅，而不依赖项目、brief、分镜或首尾帧。

#### Scenario: 独立工具调用模型

- **WHEN** 工具任务请求独立视频生成
- **THEN** 适配层使用任务中指定的允许模型 ID
- **AND** 将三个模态的参考 URL 映射为对应模型内容项
- **AND** 使用任务指定时长、画幅、固定 `720p` 和 `generate_audio=true`
- **AND** 不读取任何项目级配置或分镜字段

## REMOVED Requirements

无。
