# 视频字幕翻译规格

## 为什么（Why）

项目已有 Seed VLM 视频文字提取与定位能力，但独立视频工具尚未串联翻译、人工校对和字幕压制。新增工具将带字幕参考视频的文字、时间、位置和背景色转换为可校对译文，并通过 MediaKit 多轨剪辑生成目标语言成片。

## 变更内容（What Changes）

- 在 `/workspace/tools` 增加“视频字幕翻译”标签页。
- 接受带字幕参考视频和用户提供的无字幕视频，支持本地上传、工具视频资产选择和 HTTPS TOS URL 导入。
- 扩展现有 Seed VLM 提取结果，增加逐条字幕的背景色估计；保留文字角色、分组、单行 BBox、时间与对齐信息。
- 根据 BBox 和实际字体度量估算字号；译文保留原位置、单行显示，超宽时自动缩字号。
- 使用 `doubao-seed-evolving` 翻译为用户选择的目标语言，提供宽屏原文/译文对比校对窗口。
- 持久化工作区、阶段任务、校对草稿和渲染快照；失败可按阶段重试。
- 将无字幕视频和逐条译文编译为 MediaKit 多轨工程，异步压制并转存结果为工具资产。

## 影响范围（Impact）

- 关联能力：独立视频工具、Seed 视频字幕定位、ModelArk 文本推理、MediaKit 多轨剪辑、工具任务/资产、认证权限和 TLS 日志。
- 主要代码：
  - `frontend/app/workspace/tools/page.tsx`
  - `frontend/components/workspace/tools-workspace.tsx` 与新增字幕翻译面板、校对窗口组件
  - `frontend/lib/api-client.ts`、`frontend/lib/api-types.ts`
  - `backend/app/schemas/video_subtitle_grounding.py`
  - `backend/app/services/modelark_video_subtitle_grounding.py`
  - `backend/app/services/video_subtitle_grounding_validation.py`
  - 新增字幕翻译工作区 schema、服务、排版编译器和工具路由
  - `backend/app/api/router.py`、`backend/app/api/dependencies.py`、现有权限路由映射
  - `backend/app/schemas/tool_task.py`、`backend/app/schemas/enums.py`
  - `backend/app/repositories/` 及现有 MySQL 迁移机制
  - `backend/app/services/mediakit_multitrack.py`、现有工具资产存储与视频探测能力
  - 前后端定向测试与 Playwright 验收
- 使用当前工作树中的字幕提取实现作为基线；不回滚已有未提交改动。

## 方案选择与边界

采用分阶段工具工作区：导入 → 提取 → 翻译 → 校对 → 压制。用户确认译文后手动发起压制，修改译文只需重做压制。

其他方案的取舍：

- 一键提取、翻译、压制：操作较少，但不利于在计费渲染前校对，不作为首版主流程。
- 接入完整多轨时间线编辑器：编辑自由度更高，但增加工程与交互范围，首版使用逐条字幕属性编辑。

用户已选择：保留原位置和单行结构，译文变长时自动缩字号，不自动换行、不统一移至底部。

首版假设两份视频来自相同剪辑、起始时刻和镜头时间轴。系统不自动去除参考视频字幕，不做配音、语音翻译、自动时间对齐或视频内容相似度鉴定。允许展示分辨率不同，坐标按比例映射；时间轴差异提示用户核对，不因可恢复的质量问题整批阻断。

## 新增需求（ADDED Requirements）

### 需求：工具入口与完整流程

系统 SHALL 在 `/workspace/tools` 提供“视频字幕翻译”，沿用现有工具权限和资产选择交互。桌面显示配置、历史工作区和视频预览；校对使用宽屏 Dialog。手机配置与预览纵向排列，校对窗口可全屏，所有操作可达且页面无水平溢出。

参考视频用于提取文字；无字幕视频用于成片。两者 SHALL 独立标注、独立预览，不能静默互换。允许先提取和翻译，再补充无字幕视频。提供目标语言选择，至少覆盖英语、德语、法语、西班牙语、意大利语、葡萄牙语、中文和日语；原语言默认自动识别，可手动指定。

#### 场景：英文翻译为德语

- **当** 用户导入英文带字幕参考视频并选择德语
- **则** 用户可分别发起提取和翻译，在对比窗口检查、修改并保存译文
- **并且** 提供无字幕视频后可发起压制，查看、放大预览和下载结果。

#### 场景：输入切换

- **当** 用户选择另一工作区或导入新的参考视频
- **则** 预览与字幕数据仅来自当前工作区，不显示上一工作区的译文或成片。

### 需求：双视频导入与安全获取

系统 SHALL 对两类视频提供本地上传、可访问的工具视频资产选择和 HTTPS TOS URL 导入。URL 指 TOS 对象的 HTTPS 访问地址，可含签名参数；首版不接受裸 `tos://` URI。URL 导入先通过现有安全下载服务获取、探测并转存为工具输入资产，后续以资产 ID 引用，不依赖用户 URL 持续有效。

继承现有公网 DNS、每跳重定向、HTTPS、流式下载、512 MiB 上限和临时文件清理规则；参考视频首版沿用不超过 600 秒的提取能力边界。本地上传复用工具上传设施；如原上传设施上限较小，仅为本工具补充流式大视频路径，避免扩大其他工具默认限制。

系统 SHALL 获取两份视频的展示尺寸、旋转、时长与帧率。时间原点默认相同，不提供自动偏移。时长差超过 250ms 时显示明显提示，允许用户核对后继续；压制时剔除完全位于无字幕视频之外的片段，并将超出尾部的结束时间截到成片时长，显示调整清单。若没有可渲染片段则不提交无意义的渲染任务。

#### 场景：签名 TOS URL

- **当** 用户提交仍有效的 HTTPS TOS 签名 URL
- **则** 系统安全导入为自有工具资产，后续请求按资产获取受控访问 URL
- **并且** 签名参数不写入普通日志或工作区持久化快照。

#### 场景：不安全或损坏输入

- **当** URL 指向私网、重定向至不安全地址，或媒体不可解码、超出支持上限
- **则** 系统返回脱敏且可操作的错误，清理部分文件，不调用模型或 MediaKit。

### 需求：Seed 提取背景色

系统 SHALL 复用现有 Files API 和 Seed VLM 字幕定位适配器，默认模型 `doubao-seed-evolving`、采样 2.0 FPS。继续扫描全画面的后期字幕、标题、说明、部件标签和小号脚注，排除 Logo、包装印刷及无关背景文字；按视觉行独立输出，保留 `visual_role`、`font_height_ratio`、`alignment`、`block_id`、`line_index`。

逐条新增 `background_color: "#RRGGBB" | null`，表示该文字区域背后的代表性画面颜色，估计时排除文字字形和描边；它不是原文字颜色，也不是待绘制的字幕底板颜色。同一片段背景变化时取代表值，复杂或无法可靠估计时返回 null，不强行伪造颜色。

模型 schema 要求输出该键，领域响应允许 null；读取历史结果时缺失字段按 null 处理。背景色缺失或格式错误 SHALL 降级为 null 并标记警告，不使可用字幕整批失败。既有文字、时间、BBox 安全校验继续复用，不在本次顺带重写整个实验校验链路。

#### 场景：明亮背景

- **当** 文字位于浅色区域
- **则** 提取返回对应浅色的 `background_color`，供后链路选择高对比文字颜色。

#### 场景：复杂背景或历史记录

- **当** 模型无法可靠估计背景，或历史数据无该字段
- **则** 字幕继续进入翻译与校对，以 null 和颜色降级提示表示。

### 需求：字号估算、颜色和单行适配

系统 SHALL 区分以下数据：

- 原始文字位置：`bbox_normalized`、参考视频 `bbox_pixels`。
- 推导样式：`estimated_font_size_px`、`recommended_text_color`。
- 用户覆盖值：字体、字号、文字颜色、对齐和可选字幕底板色。
- 实际输出布局：目标视频 `render_bbox_pixels`、`effective_font_size_px` 和警告。

字号以目标视频展示空间像素为单位。先按归一化 BBox 映射至目标视频，计算框高 `h=y2-y1`；以所选字体的单行 ascent/descent 度量拟合框高，再测量译文宽度并缩小至不超过框宽。整数取整后再次测量。`font_height_ratio` 和角色仅作为辅助信息，不使用“所有字幕统一 48px”，不将 BBox 高度直接当作精确字号。

保留原对齐；缺失时按 center 降级。自动适配只缩小，不为短译文放大字号，不自动换行或省略文字。用户指定字号作为拟合上限，无法容纳时仍按单行适配并提示实际字号。最终字号至少满足供应商合法正值；过小显示警告，允许用户修改译文、BBox、字号和字体。不同视觉行及同时出现的标签保持各自位置。

背景色已知时，将 sRGB 转为线性 RGB，按相对亮度比较黑、白文字与背景的对比度，选择对比度更高者。背景色未知时默认白字并使用半透明黑色底板，同时提示用户校对。用户可覆盖文字色和底板色，低对比度只提示。场景背景色不得直接写成绘制底板色。

系统 SHALL 使用 MediaKit 支持且覆盖目标语言的字体，复用现有字体预设/字体资源；布局测量与提交使用同一实际字体文件及版本。字体覆盖不足时提供可选替代字体，不能无提示输出缺字方框。首版不承诺对每帧动态背景都达到固定对比度。

#### 场景：德语译文长于英文

- **当** 测量的德语译文宽度超过原框宽度
- **则** 字号自动缩小至单行可容纳，保留全文、原位置和对齐
- **并且** 校对窗口显示估算字号和实际输出字号。

#### 场景：旋转或不同分辨率

- **当** 参考视频为 1920×1080、无字幕视频展示尺寸为 1280×720
- **则** 坐标和字号按目标展示空间计算
- **并且** 90°/270°旋转视频依据展示方向处理，预览留边不改变输出坐标。

### 需求：按稳定 ID 翻译

系统 SHALL 为每条字幕分配稳定 `segment_id`，调用 `doubao-seed-evolving` 翻译文字，保留专有名词、数字、单位和上下文。字幕作为数据传入，不执行其中的指令。模型输出 `segment_id` 与 `translated_text`，不得改写时间、BBox、颜色或字幕顺序。

分批以 Token 预算控制，携带相邻字幕及 `block_id` 上下文，避免长视频输出截断。同一文字块按上下文翻译，但输出仍按输入 ID 对应单行。各批按 ID 合并，不能依赖数组顺序关联。

缺少 ID、重复/未知 ID、空译文或被截断的条目标记为待处理，保留已成功译文并支持仅重试失败部分或人工补齐。未得到译文的条目不能静默以原文冒充成功译文；用户可明确排除该条。未排除且没有译文的条目需补齐后才能压制。

#### 场景：模型重新排序

- **当** 翻译响应数组顺序变化
- **则** 系统按 `segment_id` 关联原文，不串行错配。

#### 场景：部分翻译失败

- **当** 一批字幕缺少部分译文
- **则** 已成功结果保持可编辑，缺失条目标记待处理，重试只处理指定缺失部分。

### 需求：原文/译文对比校对窗口

系统 SHALL 提供宽屏 Dialog，逐条显示原文和译文、起止时间、角色、背景色样本、文字颜色、估算/输出字号与警告。支持编辑译文、起止时间、BBox、字号、字体、文字色、底板色和对齐，并支持明确排除条目。原文保留作为对照，不被译文覆盖。

点击条目 SHALL 定位视频时间并显示该条的框和译文示意。预览采用 object-contain，按视频实际显示区域投影，不能把 letterbox 留边计入坐标；保护原生播放器控制。预览标注为排版示意，最终以 MediaKit 成片为准。

“保存校对”和“压制视频”是明确动作。保存使用工作区 revision，冲突时提示重新加载/处理，不覆盖远端修改；压制前保存并冻结当前 revision。关闭窗口不应无提示丢弃未保存修改。

#### 场景：保存并重新打开

- **当** 用户修改译文和颜色后保存、刷新页面
- **则** 同一工作区恢复已保存校对数据。

#### 场景：同时出现多个字幕

- **当** 同一时间有标题、说明和脚注
- **则** 窗口分别显示各条，预览和成片支持它们同时出现。

### 需求：工作区持久化、阶段任务和精确失效

系统 SHALL 新增独立字幕翻译工作区持久化实体，保存两份输入资产引用、语言、视频元数据、字幕 JSON 草稿、revision、当前阶段、active task 和最后成片引用，沿用当前仓库及迁移机制。

异步提取、翻译、压制分别复用 `ToolTask`，新增类型 `video_subtitle_translation`，通过 `input_snapshot.operation=extract|translate|render` 与 `workspace_id` 区分阶段；每次操作创建独立任务，沿用 queued/running/succeeded/failed，不为本工具修改全局任务状态枚举。工作区另行记录 draft/extracting/extracted/translating/review_ready/rendering/succeeded/failed。

阶段快照只存稳定资产引用及规范化输入。修改参考视频使提取及后续结果失效；修改目标语言使译文及成片失效；修改无字幕视频、译文、时间或样式只使成片失效。失效的历史结果仍可追溯，但不能作为当前结果展示。

重复提交同一操作及 revision SHALL 幂等，不能重复计费；失败重试创建关联旧任务的新任务，保留已完成阶段。任务完成回写校验 active task 和 revision，晚到结果不能覆盖新草稿。MediaKit 已提交任务可凭 provider task ID 恢复轮询；应用重启后未提交或无法恢复的本地模型阶段标记为中断失败并允许重试，不长期卡在 running。

#### 场景：仅修改译文

- **当** 用户修改一条译文并重新压制
- **则** 复用提取结果和其他译文，只发起新的压制任务。

#### 场景：旧任务晚到

- **当** 用户更新输入后旧任务完成
- **则** 旧结果保留在历史任务中，不覆盖当前工作区。

### 需求：MediaKit 多轨压制

系统 SHALL 复用 `MediaKitMultiTrackClient`，调用 `POST /api/v1/tools/multi-track-edit` 和任务查询接口。底层视频使用用户的无字幕视频，保留其音轨；没有音轨则输出无音轨成片。输出为 MP4，保持展示尺寸和方向，帧率使用支持的源帧率，否则使用 30 FPS 并提示。

译文使用逐条 text 元素，带独立时间、位置、字体、有效字号和颜色；根据时间重叠分配轨道，保证同帧多位置文字可同时出现。字幕文字按供应商纯文本/转义规则传入，不能意外解释为样式指令。坐标、位置锚点、文字度量和 transform 映射需使用可验证的渲染契约，不能通过整体拉伸 text 元素变相改变字号。

本工具复用供应商客户端和字段映射，不依赖画布节点或连接，不机械继承时间线编辑器的 20 轨/200 元素 UI 上限。实施时先核对现有供应商契约的容量；超过已确认容量时明确显示支持边界并保留草稿，不静默截断，不承诺未验证的供应商容量，也不引入多次有损拼接作为隐式回退。

提交使用工作区 ID、revision、内容摘要生成稳定 client token。渲染失败可基于冻结快照重试，不重跑提取或翻译。结果在供应商临时 URL 有效期内流式转存为工具输出资产，转存与数据库关联完成后才标记成功。失败清理部分对象，防止重复资产。

#### 场景：压制成功

- **当** 所有包含的字幕都有译文且用户发起压制
- **则** MediaKit 接收无字幕视频和逐条文字轨道
- **并且** 完成后结果进入工具资产库，可在本工具预览、放大和下载。

#### 场景：渲染或转存失败

- **当** MediaKit 失败、轮询超时或输出转存失败
- **则** 显示阶段错误并允许重试，保留校对数据，不创建虚假成功结果。

### 需求：接口与权限

新增 `/api/tools/subtitle-translation` 路由组：

- `POST /workspaces`：创建工作区，可仅提供参考资产和目标语言。
- `GET /workspaces`、`GET /workspaces/{id}`：列表和详情，详情包含当前草稿、阶段任务引用与输出引用。
- `PATCH /workspaces/{id}`：携带 expected revision 更新输入、语言和校对内容，执行精确失效。
- `POST /workspaces/{id}/extract`、`/translate`、`/render`：返回持久化阶段 ToolTask；translate 可指定待重试 segment ID。
- `POST /import-video`：导入 HTTPS TOS URL，返回工具输入资产；本地上传沿用工具资产上传协议。
- 阶段任务查询和失败重试扩展现有 `/api/tools/tasks/{task_id}` 与 `/retry`。

新增路由 SHALL 接入既有 RBAC 映射：管理员/有工具执行权限的 Creator 可创建、编辑和执行；Viewer 可按现有资源可见范围读取，不能导入、编辑、翻译或压制；未登录返回 401。资产访问验证沿用现有规则，不能因传入任意资产 ID 绕过权限。生产工具执行不借用管理员实验开关，也不放开原实验接口权限。

#### 场景：只读用户

- **当** Viewer 直接请求阶段执行或草稿更新接口
- **则** 返回 403，且不触发下载、模型或 MediaKit 请求。

### 需求：可观测性与验收

系统 SHALL 将导入、提取、翻译、保存、提交、轮询、转存与失败事件作为结构化 JSON 写入 TLS，记录工作区/任务 ID、revision、阶段、模型、片段数、Token 和耗时。模型原文仅进入现有 TLS-only 调试通道，不能进入 stdout、本地控制台或 API 错误；持久化的是业务字幕数据，不是原始模型响应。URL 查询参数、凭据和字幕全文不进入普通日志。

普通自动化使用 Mock，不调用计费模型或 MediaKit。验证包括后端契约/服务/权限/持久化测试、字体测量与轨道编译测试、前端校对与失效测试、lint、TypeScript、build、Ruff 致命检查、编译和 git diff --check。Playwright 使用 1440×900、834×1112、390×844 验收。

真实模型识别质量、德语字形及供应商最终渲染属于另行显式授权的真实验证；未实际运行时必须在最终结果中标明未验证，不以 Mock 冒充真实效果。

## 修改需求（MODIFIED Requirements）

### 需求：字幕提取数据兼容

既有字幕提取 SHALL 增加可空背景色字段并兼容历史缺失值，保留当前单行、分组、角色、时间与坐标语义。实验接口既有访问权限和开关保持原有规则。

### 需求：工具任务与资产

工具任务 SHALL 支持字幕翻译的阶段类型、快照、查询和重试；结果作为工具资产出现。现有人物打码、全模态参考生视频、工具资产预览和资产库筛选继续可用。
