# 图片编辑画布 CPU 性能优化 Spec

## Why
打开图片编辑画布后，浏览器 CPU 利用率可能持续接近 100%，影响画布操作、页面响应和设备功耗。需要先以运行时证据定位持续计算来源，再实施最小范围修复并证明优化有效。

## What Changes
- 建立 `canvas-cpu-spike` 调试会话，在不改业务逻辑的前提下采集画布打开、稳定空闲和交互阶段的运行时证据。
- 对 React Flow 节点状态更新、React 提交、bbox 尺寸观测、布局测量、任务轮询及资源创建/销毁进行最小化插桩。
- 在同一浏览器、同一项目数据和同一操作路径下形成修复前基线，确认或排除高频重渲染、尺寸观测反馈循环、资源泄漏和轮询异常等假设。
- 仅针对证据确认的根因实施最小修复，不改变画布现有视觉、节点交互、bbox 坐标语义和布局持久化协议。
- 使用修复后日志、浏览器性能数据和自动化回归测试完成前后对照；用户确认后清理全部临时调试产物。

## Impact
- Affected specs: 图片画布节点编辑、参考图 bbox、输出任务轮询、画布布局持久化
- Affected code: `frontend/components/workspace/image-canvas-page.tsx`、`frontend/components/workspace/canvas/bbox-canvas.tsx`、`frontend/components/workspace/canvas/node-canvas.tsx`、相关节点组件与前端测试

## ADDED Requirements
### Requirement: 运行时证据驱动的 CPU 根因定位
系统 SHALL 在修改业务逻辑前建立可重复的性能基线，并以运行时证据确定 CPU 持续升高的调用来源。

#### Scenario: 采集修复前空闲基线
- **WHEN** 在同一浏览器中打开指定图片项目画布并停止操作至少 10 秒
- **THEN** 系统应记录该阶段的 CPU 时间线、React 提交频率、节点状态更新频率、bbox 尺寸观测与布局测量频率、任务轮询频率
- **THEN** 证据应区分空画布、含参考图节点画布和含待处理输出节点画布

#### Scenario: 判定候选根因
- **WHEN** 完成一次可稳定复现 CPU 飙升的修复前采样
- **THEN** 调试记录应将以下假设逐项标记为 CONFIRMED、REJECTED 或 INCONCLUSIVE，并引用对应日志或性能采样证据：
  - React Flow 节点变更与页面状态之间形成持续更新循环
  - `ResizeObserver`、DOM 尺寸测量和状态写回形成布局反馈循环
  - 定时器、监听器、观察器或动画任务未正确释放并持续累积
  - Context 值或回调身份变化导致画布节点无必要地高频重渲染
  - 输出任务轮询在无待处理任务时仍持续运行，或因节点更新重复调度

### Requirement: 最小范围性能修复
系统 SHALL 仅在运行时证据确认根因后修改相关逻辑，并保持既有用户行为与数据契约不变。

#### Scenario: 尺寸观测或渲染循环被确认
- **WHEN** 证据显示观察回调、布局读取、状态写入或组件提交在空闲阶段持续自激
- **THEN** 修复应打断反馈链路、跳过无实质变化的状态写入，并确保观察资源在卸载时释放

#### Scenario: 节点状态或轮询循环被确认
- **WHEN** 证据显示节点更新或任务轮询在输入未变化时重复调度
- **THEN** 修复应稳定依赖项与状态引用，并仅在实际节点数据或任务状态变化时更新

#### Scenario: 其它候选均被排除
- **WHEN** 证据指向上述假设之外的单一热点
- **THEN** 调试记录应补充新假设及证据，并将修复限制在该热点及必要测试范围内

### Requirement: 可量化的性能验收
系统 SHALL 在相同环境和复现路径下比较修复前后结果，证明空闲 CPU 飙升已消除。

#### Scenario: 打开画布后保持空闲
- **WHEN** 修复后打开同一画布并在资源加载完成后静置 10 秒
- **THEN** 浏览器渲染进程 CPU 不应再持续接近 100%
- **THEN** 稳态采样期间 CPU 中位值应较修复前下降至少 70%，且高频回调或状态更新应在 2 秒内收敛至无持续自激

#### Scenario: 执行核心画布交互
- **WHEN** 用户平移、缩放、拖拽或缩放节点、绘制或删除 bbox，并等待布局保存
- **THEN** 操作应保持可响应，停止操作后 CPU 与插桩计数应重新收敛
- **THEN** bbox 显示位置、图片宽高比、节点布局保存和输出任务轮询行为应保持正确

### Requirement: 调试产物生命周期
系统 SHALL 使用 `debug-canvas-cpu-spike.md`、`.dbg/canvas-cpu-spike.env` 和 `.dbg/trae-debug-log-canvas-cpu-spike.ndjson` 维护证据链。

#### Scenario: 用户确认修复
- **WHEN** 修复前后证据已完成且用户确认问题不再复现
- **THEN** 系统应移除全部临时插桩、停止调试服务器并删除该调试会话的记录、环境和日志文件

#### Scenario: 用户中止排查
- **WHEN** 用户选择中止调试
- **THEN** 系统应移除全部临时插桩、停止调试服务器并删除该调试会话的全部临时产物，同时保留规格文档

## MODIFIED Requirements
### Requirement: 图片编辑画布运行效率
图片编辑画布 SHALL 在打开、空闲及常规交互阶段避免无输入驱动的持续渲染、布局测量、状态写入和轮询，同时保持现有节点画布功能不变。

#### Scenario: 画布资源加载完成
- **WHEN** 项目数据、图片和节点完成首次加载
- **THEN** React Flow、参考图节点、输出节点和右侧配置面板不应因稳定数据产生无限或高频更新循环

## REMOVED Requirements
无。
